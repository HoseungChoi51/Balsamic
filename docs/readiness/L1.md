# L1 — An install keeps what campaigns use; every version is archived

State: implemented and tested (PR on branch `claude/project-thread-fcyj4d`, 2026-10-28); not checked live (see the acceptance test).

## What was wrong

Layer: evidence. An install replaced a library's folder whole, so a new version could take away a method or problem another
campaign's runs and proposals rested on, and the version it replaced was deleted.
Invariant: INV-L1-1 (added), INV-L1-2 (added).

- A coding workspace writes to `libraries/<problem id>/`, so every campaign on a problem writes to the same library. If
  campaign B delivered a version without campaign A's methods, they disappeared from the lab; replacing the same library
  was not a change that needed the researcher's confirmation.
- A kept method that failed validation outside the box (H6) was refused for every campaign, including those that ran it.
- Nothing kept the old version.

## What changed

| Change | Where |
|---|---|
| What the lab's campaigns use, lab-wide: a method a run ran or a proposal is bound to, a problem a task is on | `agents/library_usage.py` |
| After validation outside the box and before uv runs, the install compares the installed version's methods and problems (what the installed package provides now) with the new version's (the methods validation listed and passed, the problems its entry points name). A dropped method or problem a campaign uses, or a kept method that fails validation, refuses the install, naming each one and the campaigns, and saying what to do: keep it, give a changed method a new name, make a changed scoring function a new problem id (decision 25). The coding agent gets the reason as with any failed install | `agents/library_install.py` `Installer._keeps()`, `provided()`, `install()` |
| The install records what it keeps and removes (`methods_kept`, `methods_removed`, `problems_kept`, `problems_removed`); the notice and the install card say it in a line | `agents/library_install.py` `kept_text()`; `frontend/src/hypotheses/Implementations.tsx`, `workspace.ts` |
| Every installed version is archived on the host, `<data>/library_archive/<name>/<version>/` (its files and `version.json`: package, version, install, campaign, workspace, submission, commit, methods, problems); the version an install replaces is archived first when it is not yet. The install records its archive | `agents/library_install.py` `archive()`, `Installer._archive_replaced()`, `lab_files()` |
| The install docs say what a new version must keep | `docs/optimizer-plugins.md` |

## Checked

- `tests/test_library_keep.py`: usage is lab-wide (runs, bound proposals, tasks); a version that leaves out a method another
  campaign ran is refused before uv runs and the lab's copy is unchanged; a kept used method that fails validation refuses
  it; a version that leaves out a problem a task is on is refused (an unused one is not named); an unused method may go and
  is recorded as removed, and both the replaced and the new version are archived with their files and origin; a first
  install keeps nothing and says nothing of it.
- `tests/test_library_install.py` unchanged and passing; `frontend/tests/implementations.spec.ts`: the card says what the
  install kept and removed.
- Full runs at the PR's head: see the PR.

## Not done

- Whether a kept method still behaves the same is L4's (it replays recorded runs); L1 checks only that it is there and
  passes validation.
- The archive is plain folders; L2 makes each library a Git repository with tagged versions and imports these archives.

## Acceptance test

1. Start the lab with coding workspaces on. In campaign A, let a coding workspace deliver a package with two methods and
   run one of them.
2. In campaign B on the same problem, have the coding agent deliver a new version of the package without the method A ran.
3. On B's Implementations page, the install is refused: the card names the method, says campaign A uses it, and says to keep
   it (a changed method gets a new name).
4. Have the agent deliver a version that keeps it and adds a method. It installs, and the card says how many methods it
   keeps of the version it replaced; A's runs still show their method as installed.
