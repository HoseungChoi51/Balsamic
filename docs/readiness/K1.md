# K1 — A `compute` tool on the charter's expression evaluator

State: implemented and tested (PR #34, 2026-10-27); not checked live.

## What was wrong

Agents did arithmetic in their heads, or wrote a script and ran it with `analysis_run` (two steps, described only in the
`analysis-scripts` procedure). In readiness Part J the operator called a mutation rate of 0.005 "about 1/n" for 32,768
cells, where 1/n is 0.00003 and the rate is 163.84 times it. The charter's whitelisted evaluator computed the charter's
numbers and nothing else, and no record said where a number in a reply came from.

## What changed

| Change | Where |
|---|---|
| A `compute` tool: `{expression, values}`, at most 50 values, each a number or `{record_id, pointer}`, a number read from a record the agent may read (`record()`) at an RFC 6901 pointer. The backend evaluates with `expressions.evaluate()`; errors are the evaluator's, a value the expression does not read, text or a boolean at the pointer, and a text result are refused | `agents/tools.py` `TOOLS["compute"]`, `PiTools.compute()` |
| The result is the computation, and the call's `agent_tool_receipt` keeps it: `{expression, value, inputs: [{name, value, record_id, pointer}], receipt_id}` (`record_id` and `pointer` are null for a literal). K2 reads it | `agents/tools.py` `PiTools.compute()` |
| Who has it: the lead, the four page agents, and the specialists whose role files list it (`results_analyst`, `empirical_assessor`, `methodology_specialist`, `skeptical_domain_analyst`). Not the proposal reviewer, the literature specialist, the cross-domain explorer or the implementation grant's roles | `agents/tools.py` `PiTools.names()`, `agents/roles/*.md` |
| One sentence in `INSTRUCTIONS` ("Derive a number with compute or a script, never mental arithmetic"), and the same rule in `SPECIALIST_CONTRACT` in place of its sentence on numbers. Under the size ratchet with nothing added: the shared core is 388 words as before (the example of a question answered without actions went; the rule it illustrated stays), the lead's contract lost "the result comes back to you" (the tool's description and its result say so), and the specialists' sentence kept its length | `agents/tools.py`, `agents/roles.py` |
| The chat's label: "Computing a number" | `agents/tools.py` `STEPS` |
| The tool described for maintainers | `docs/pi-agent-harness.md` "Files and the agents' own analysis" |
| INV-K1-1 added next to INV-19 | `docs/invariants.md` |

## Checked

- `tests/test_compute_tool.py`: `compute` with literals, with a pointer into a trial's record, and with both, each input
  naming its source, and the receipt holding the same result; Part J's case, `rate / (1 / n)` with 0.005 and 32,768,
  gives 163.84. A pointer into another campaign's trial is refused, as are a missing field, text or an object at the
  pointer, a boolean, an unused value and 51 values. An expression over 1,000 characters, a call of `__import__`, an
  attribute, an unknown name and a division by zero are refused with the evaluator's text, and none of them reached
  `eval`. The lead and the four page agents have the tool; exactly the four specialists listed have it; a builder does not.
- `tests/test_harness_contract.py`: the prompt-size ratchet holds; `tests/test_invariants.py`: the new row's pins exist.

## Not done

- A protected record (a locked confirmation result) is read like any other until V4; then `record()` refuses it, and
  `compute` with it.
- Nothing checks yet that a number in a reply came from a `compute` receipt: that is K2.
- No eval scenario pins the instruction to use `compute` instead of mental arithmetic (an I2 scenario could).
- Not checked live: no agent has used the tool on the dev stack.

## Acceptance test

1. Start the app and open a campaign with at least one finished run.
2. In the lead's chat, ask: "A mutation rate of 0.005 on a grid of 32,768 cells: how many times 1/n is that?" The chat
   should show a step "Computing a number", and the answer should be 163.84 (not "about 1/n").
3. Ask: "How far is the best run's score from 1?" The chat should show "Computing a number", and the answer should match
   1 minus the best score the Experiments page shows for that run, naming the run.
4. On the Hypotheses page, ask the discussion moderator for a results analyst's view of a finished run that needs a ratio
   or a difference (for example, how much better one run's best score is than another's, in percent). The analyst's
   steps, in the review round, should include "Computing a number", and its numbers should agree with the Experiments page.
