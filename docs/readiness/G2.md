# G2 — The same flow as a live quality scenario

State: implemented and tested offline (PR #TBD, 2026-10-27); the live run on Centinels is Hoseung's (see the acceptance test).

## What was wrong

Layer: prompt. Phase 1 made Balsamic carry the steps after a go-ahead (install, adopt, bind, start the runs), but no
scenario put the whole flow to a real lead: nothing showed that a model, asked once and approved once, goes from a
confirmed charter to ranked results without binding, starting runs or asking for more, nor how long that takes.
Invariant: INV-G2-1 (new).

## Acceptance test

A live eval, for Hoseung, on the release commit of Phase 1. It uses the dev profile's model on Centinels, so it needs no
approval, and it takes about an hour.

Before you start: Docker running, the coding workspace image built (`docker build -t grating-implementation-workspace:pi-1.3.0
deploy/implementation-workspace`), your Centinels sign-in in `~/.config/balsamic/secrets.env`. The run installs the library
the coding workspace delivers into the checkout it runs from, so run it from a worktree of its own:

```bash
git worktree add ../balsamic-g2 phase-1     # the Phase 1 release tag, or its commit
cd ../balsamic-g2 && uv sync --extra dev && (cd agent-harness && npm ci --ignore-scripts && npm run build)
uv run python scripts/run_lead_evals.py --scenarios S19 --record-baseline
```

What should happen:

1. The run prints `S19-charter-to-results #1: pass`.
2. In `runs/evals/<time>/summary.md`, S19 is `pass`, and "Go-ahead to ranked results" gives the time in minutes. Write it
   down: it is Phase 1's time from go-ahead to ranked results.
3. In the transcript (`runs/evals/<time>/transcripts/S19-charter-to-results-r1.md`), every check is PASS: one compute
   request; no binding and no run by any agent; every run started by `balsamic`; a comparison report; 2 researcher actions;
   the lead's last reply lists exact enumeration first (about 290 min late) and earliest due date last (about 415).
4. The baseline file `evals/lead/baselines/<commit>-centinels-<model>.json` is written in the worktree; copy it into your
   main checkout and commit it.

If a check fails, the transcript's Checks section says which and why; send it to a thread. Afterwards, remove the worktree
(`git worktree remove ../balsamic-g2`).
