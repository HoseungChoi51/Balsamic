# I3 — Docs small and dated

State: implemented and tested (2026-10-27); no live check needed, the part changes docs and one test only.

## What was wrong

A new reader of `docs/` met 54 files with no index: a 1,773-line consolidation log and a 1,104-line readiness log before
the design, fourteen documents of the service before the 19 October rebuild sitting beside the current ones with only a
banner to tell them apart, two superseded plans without even that, and no single page saying what works now. The harness
plan still listed its decisions D1–D9 as "Open" although Phases 1–7 had been built and checked live at their defaults.
Decisions lived in commit messages and long plans, not in records a reader could find.

## Checked

- `tests/test_docs_links.py` (5 tests) and `tests/test_invariants.py` pass. The link test's own fixture checks that a
  missing file is reported and that web links, anchors and code blocks are skipped.
- The test fails where it should: run on `main` with the documents moved but no link rewritten, it reports 268 broken
  links (to, from and between the moved documents, and the ten to removed code); on this branch, none.
- Each harness-plan decision was checked against Parts L–R of the readiness log before it was marked.
- Each ADR's commit exists in the history (`git log -1 <commit>`).

## Not done

- The roadmap's own files still name the moved documents at their old paths, in backticks, as they were at `cc0e693`;
  they hold no Markdown links to them. The history index says so. Roadmap files are edited only to correct mistakes.
- No row of `docs/invariants.md` changes: the part adds no guarantee about the agents.
- `docs/status.md` is written by hand. It changes when a phase completes, and the register stays the source for the gaps.

## Acceptance test

None in the app: the part changes only documentation. To check it, open the repository on GitHub at `main` after this
part has merged:

1. Open `docs/README.md`. Expect an index in reading order, design first, with every link opening a page.
2. Open `docs/status.md` from it. Expect what works today, the seven roadmap phases with their state, and the known gaps
   with the roadmap part that closes each.
3. Open `docs/history/README.md`. Expect 17 old documents, each with its date and what replaced it; open two of them and
   check that each starts with a "Superseded" banner.
4. Open `docs/adr/README.md`. Expect eight short decision records, each with a date and a commit.
5. In the `docs/` folder itself, check that no superseded plan sits beside the current documents.
