# F2 — Export as a Python project

State: implemented and tested (PR #PRNUM, 2026-10-27); the acceptance test is Hoseung's.

## What was wrong

Layer: none. F2 adds a way out of Balsamic; it fixes no failure of an agent or a guardrail.
Invariant: none, an export changes nothing in the lab, and the tests below pin what it contains.

- A researcher could not take the charter to their own tools. F1 generates the project, but nothing in the app handed it
  over.

## What changed

| Change | Where |
|---|---|
| `archive(charter, revision, *, name=None, charter_id=None)` zips `scaffold()` under `<project-name>/` and names the file `<project-name>-r<revision>.zip`. Pure like `scaffold()`: fixed timestamps and sorted paths, so the same revision gives the same bytes | `problem_charter/scaffold.py` |
| `GET /api/v1/problem-charters/{id}/revisions/{n}/export.zip` returns that zip as an attachment. A missing revision answers 404; a charter the generator refuses (no objective, no decision variables, a value that does not resolve) answers 409 with the reason | `problem_charter/api.py` |
| An "Export as Python project" button in the Charter tab's header downloads the revision on screen, confirmed or not. A refusal shows on the tab as "Could not export the charter: <reason>" | `frontend/src/note/CharterPanel.tsx` |
| The export described next to the Charter tab's other routes | `docs/ui-workspace.md` |

## Checked

- `tests/test_problem_charter_export.py` (3 tests): the archive is exactly the scaffold's files under the project folder,
  named after the problem and the revision, and the same bytes twice; the endpoint returns revision 1 and revision 2 of an
  edited charter, each with its own `charter.json` (charter id, revision, the value as of that revision) and
  `pyproject.toml`; a missing revision is 404 and a charter with no objective is 409 naming the reason.
- Playwright `charter.spec.ts`, "Export as Python project downloads the revision on screen as a zip, and says why when it
  cannot": the button asks for the revision on screen, the browser saves the file under the name the service gives, and a
  refusal shows on the tab. All 13 charter tests pass; `npx tsc -b` is clean.

## Acceptance test

1. Start the app and open a campaign whose problem note has been adopted, so it has a charter. Go to the problem note's
   Charter tab.
2. In the header, next to the revision pill (for example "ready to confirm · r3"), press **Export as Python project**.
   The browser saves a zip named after the problem and that revision, such as `flow-reactor-yield-r3.zip`.
3. Open the zip. It holds one folder with `README.md`, `pyproject.toml`, `charter.json`, a package folder (`data.py`,
   `problem.py`, `objective.py`, `methods.py`, `harness.py`, `compare.py`) and a `tests` folder. `charter.json` gives the
   same revision number as the pill, and the values in `data.py` are the charter's. `objective.py` holds the objective's
   definition in words, waiting to be written; `README.md` says how to run the tests and the comparison.
4. Change one value on the Charter tab (the pill moves to the next revision) and export again: the new zip carries the
   new revision in its name and the new value in `charter.json`. Exporting the same revision twice gives identical files.
5. Optional, with your own tools: in the unzipped folder, with numpy and pytest installed, the tests run; until you write
   the objective, only the tests that need it fail, saying the objective is not written yet.
6. If a charter has no objective yet, the button does not download anything: the tab shows "Could not export the
   charter: The charter has no objective".
