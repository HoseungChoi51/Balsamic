# C3 — Library methods say what they accept

State: implemented and tested (PR #12, 2026-10-27); the live check is Hoseung's.

## What was wrong

- `PackagedPlugin.methods()` gave every method that declared no `representations` the value `["binary"]`, and a library
  had no way to declare it once for all its methods. A library built for a continuous, discrete or (later, C1) permutation
  problem that left it out showed every method as unable to run on its own problem, with only "requires binary
  candidates" as the reason, which does not say what to change.
- The optimizer_v1 context named the candidate's length `n_cells`, the grating's word, and nothing else.

## What changed

| Change | Where |
|---|---|
| `PackagedPlugin.REPRESENTATIONS`: a method takes its own `representations`, else the class value, else `["binary"]` as before. A method left on that default carries `representations_defaulted: true` in its descriptor | `optimizers/packaged.py` |
| A method incompatible only because it took the binary default says "… requires binary candidates: the library declares no representations, so it is treated as binary; declare REPRESENTATIONS". This reason reaches the Algorithms list, the lead's method listing and `create()` | `optimizers/registry.py` `capability_reason()` |
| The optimizer_v1 context carries `dimensions` beside `n_cells` (same value), in-process, in a sandboxed package run and in implementation validation | `optimizers/packaged.py` `PackagedOptimizer`, `execution/worker.py`, `implementations/validation.py` `context()` |
| `REPRESENTATIONS`, the binary default and its reason, and the context's keys documented; `n_cells` marked deprecated | `docs/optimizer-plugins.md` |

The grating library (`libraries/grating-mask-search`) is unchanged and lists its methods as before; they now also carry
`representations_defaulted`.

## Checked

- `tests/test_library_representations.py`: a library with `REPRESENTATIONS = ["continuous"]` is compatible with a
  continuous problem (`bounded_continuous`) and runs on it; a method's own `representations` overrides the class value; a
  method on the binary default gives the reason above, also from `create()`; the context has `dimensions == n_cells`; the
  grating library's three methods are listed as before (binary, unconstrained, its problem id, no parameters). The new
  file fails on `main` without the change (4 of 4).
- The neighbouring suites pass: `tests/test_packaged_optimizers.py`, `tests/test_method_finish.py`,
  `tests/test_method_catalog.py`.
- The full suite, as in the PR.

library a coding workspace delivered for it.

- [ ] C3: a library method that declares no representations says why it cannot run

  2. Have the lead build a method for it in a coding workspace, and let Balsamic install the library.

  Expect: if the library declares what it accepts, its methods are listed as able to run on the task. If it does not,

  treated as binary; declare REPRESENTATIONS".
