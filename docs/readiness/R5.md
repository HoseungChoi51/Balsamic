# R5 — The model-spend envelope

State: implemented and tested (PR pending, 2026-10-27); nothing to check live yet (see the acceptance test).

## What was wrong

Layer: budget. Model spend was capped only per campaign (`llm_budget_usd`), and a model call did not say which run or
which request it was made for, so one request could spend the whole campaign's model budget and nobody could tell which.
Invariant: INV-R5-1, INV-R5-2, INV-R5-3 (new, next to INV-10).

## What changed

| Change | Where |
|---|---|
| `llm_usage` gains `run_id` and the request root (`root_thread_id`, `root_message_id`, `root_run_id`), nullable: a table made before is altered in place and its old rows name none | `agents/usage.py` `SCHEMA`, `ensure()` |
| `record()` fills them: the run is the one the harness event names, else the agent's run at work (an older harness names none); the root is the run's request: a lead turn's `request_root()`, an assistant's or page agent's assignment, else the request it was asked in | `agents/usage.py` `record()`; `agents/controller.py` `run_root()`, `_event_run()` |
| The harness names the run in each `assistant.message` event | `agent-harness/src/supervisor.ts` |
| A report job keeps the run that asked for it and that run's request; its stages' calls are recorded under them | `reports/writer.py` `start()`, `capture()`; `agents/tools.py` (`report_write`) |
| A mandate's model spend is the API dollars of the calls under its request (lead, assistants, page agents, report stages), matched as `same_root()` matches requests, plus any dollars charged on it directly; a standing mandate's is the campaign's since its grant. Subscription calls are not charged, as for the campaign cap | `agents/usage.py` `spent()`; `campaigns/mandates.py` `model_spent()`, `read()`, `model_left()` |
| When the newest mandate in force for a request has spent its model envelope, new turns under that request hold at dispatch, as `_within_llm_budget()` holds the campaign's; other requests go on. The first hold puts one inbox card (a decision, kind `mandate_model`) to raise it by the envelope's size; approving it records the raise with the decision and the held turns go on at the next pass | `agents/controller.py` `_within_mandate_spend()`; `campaigns/mandates.py` `current()`, `hold()`, `raise_model()`; `campaigns/approvals.py` `resolve()` |
| A report stage the request's envelope cannot cover at its upper bound is not started, as for the campaign's budget | `reports/pipeline.py` `afford()` |
| The state block of the lead and the page agents names the mandate in force for the turn's request and the model dollars it has left, or that it has no envelope of its own; nothing when no mandate is recorded (R2 adds "none: Explore by default") | `agents/turn_state.py` `mandate_line()` |
| INV-R5-1 to INV-R5-3, next to INV-10 | `docs/invariants.md` |

The campaign cap is unchanged and still holds every turn, with or without a mandate.

## Checked

- `tests/test_model_envelope.py` (5 tests): usage rows carry the run and request of a lead turn (by the agent's run at work
  when the event names none), of an assistant sent for that request, and of a page agent asked from another thread; a call
  in no request names none; a mandate's spend is its own request's API dollars only, a standing mandate's the campaign's
  since its grant; a table from before gains the columns and keeps its rows; a notice under a spent envelope holds, one card
  is filed however many passes, the state block says the envelope is spent, approving the card raises it and the turn goes;
  another request goes on beside a spent one, and at the campaign cap a request with no mandate holds as before (the
  `llm_budget` issue, no mandate card); a mandate without an envelope never holds.
- `tests/test_report_harness_model.py::test_report_stages_count_under_the_request_that_asked_and_stop_at_its_envelope`: a
  report's stages are recorded under the asking run and request, and the stage the envelope cannot cover is not started.
- `agent-harness` `npm test` (35 tests), with the `assistant.message` event's run checked in `supervisor.test.mjs`.
- `tests/test_mandates.py`, `tests/test_pi_models_usage.py`, `tests/test_turn_state.py`, `tests/test_invariants.py` pass unchanged.

## Not done

- Nothing grants a mandate with a model envelope yet: R2's `mandate_propose` and R7's dial do. Until then the hold and the
  card never appear in the app.
- When a standing mandate and a request's own mandate both serve a request, only the newer one is checked.
- A report job started by the researcher on the Reports page belongs to no request and counts only against the campaign cap.
- The card raises the envelope by its own size; the researcher cannot type another amount on it (R7 may).

## Acceptance test

None: R5 counts model spend per request and holds turns once a request's mandate has spent its model envelope, but nothing
in the app grants a mandate with an envelope until R2 (the lead proposes one) and R7 (the mandate dial in the chat). It shows
in `tests/test_model_envelope.py`. What a user can check now is that nothing changed: with a small LLM cap on a campaign,
the agents stop at the cap with the same "Agent turns are on hold" notice as before, and raising the cap lets them go on.
