# V4 — Locked results stay unreadable to agents until release

State: implemented and tested (PR #38, 2026-10-27); merges after the `baseline` tag and after V3. The live check (S15)
is Hoseung's.

## What was wrong

- **The agents' read tools ignored the lock.** `CampaignGuidance._records()` (the roadmap calls it `MemoryService`)
  computes what an agent may see: locked splits, unreleased cohorts and whatever refers to them. Only `finding.record`
  used it. `evidence_read` checked only that a record's kind was readable and that it belonged to the campaign, so a
  confirmation cell's trial, its result and its metrics were readable before release.
- **Every other path was open too.** `evidence_search` listed every readable record, `file_list`, `file_read` and
  `file_search` opened any trial's experiment directory, `analysis_run` mounted any trial, `experiment_progress` showed
  the cells' best scores, and a `comparison.report` an agent ran put the cells in its groups.

## What changed

| Change | Where |
|---|---|
| `protected(campaign_id)` returns the ids `_records()` withholds and, for each, the view an agent reads instead (a trial reads as its status, an issue and its message as the operational notice `_records()` already gave). `protected_ids()` returns the ids. Cached by the campaign's event cursor and the store's write counters, so the walk runs once per change; a transaction that wrote records walks again. The walk moved into `_walk()`, its kinds into `WALKED` and its reference scan into `linked_ids()`; `_records()` returns what it did | `campaigns/guidance.py` |
| `record()` returns the view of a withheld id, refuses any other withheld id with "withheld until the confirmation is released", and refuses a readable record outside the walk (a tool receipt, a run, a report) that names withheld evidence. Every tool that reads by id goes through it | `agents/tools.py` `PiTools.record()` |
| `evidence_search` leaves withheld ids out (the offset still counts them, so paging goes on) | `agents/tools.py` |
| The experiment root of `file_list`, `file_read` and `file_search`, and `analysis_run`, refuse a withheld trial | `agents/files.py` `Files.root()`, `analysis_run()`; `PiTools.withheld()` |
| `experiment_progress` shows a withheld trial as its kind and status only: no id, score, trend or measurement | `agents/experiments.py` `progress()` |
| An agent's `comparison.report` leaves the withheld trials out and counts them (`withheld_runs`); naming one in `trial_ids` is refused. The researcher's comparison has them | `campaigns/commands.py`, `analysis/general.py` `report()` |
| `lab_events` leaves out lines that are withheld | `src/balsamic/lead/tools.py` |
| INV-18 is `code`, pinned by the new tests | `docs/invariants.md` |

## Checked

- `tests/balsamic/test_locked_confirmation_reads.py` (4 tests): a confirmation with two finished cells on a heldout task
  and no release. Before release, no result of `campaign_inspect`, `evidence_search`, `evidence_read`,
  `experiment_progress`, `file_list`, `file_read`, `file_search`, `analysis_run`, an agent's `comparison.report` or
  `lab_events` names a cell or holds its score; the cell reads as its status; the file tools and the analysis are
  refused. After `release()`, every one of them returns the cells. A finding and a saved tool receipt that name a cell
  stay withheld; a comparison naming a cell is refused for the agent and runs for the researcher; the protected set is
  walked once until the campaign changes.
- `test_every_tool_is_checked`: every agent tool (the core's and the service layer's) is either a read called by that
  test or says why it returns no campaign record, so a new tool fails until it is classified.
- `scripts/test-changed`: 188 passed, 10 skipped. The full suite: see the PR.

## Not done

- `resource_inspect` still lists running confirmation jobs by id, with their processes and seconds (no result or score):
  the resource planner manages them. If J1's `no_reads_of` check counts ids in results, S15 can still fail on it; then
  that tool would show them without ids too.
- What a turn's context brings in by itself, outside the read tools (the thread transcript, pinned records' kind and
  status, page summaries), is not filtered here; it carries no results of its own, but a researcher's message that quotes a
  score reaches the lead.
- A protected trial reads with the cohort message ("Predeclared cohort work; results withheld until evidence release")
  even when the lock is a heldout split rather than a cohort.
- The live S15 trap (J1) has not run: J1 is not merged yet.

## Acceptance test

Use a campaign with the lead agent switched on and a confirmation whose runs have finished but which has not been
released. J1's S15 seed (`unreleased_confirmation`) makes one; a finalist's confirmation that has finished its runs is
another.

1. On the Experiments page, find the confirmation's runs. You can see that they finished, and their scores; the agents
   cannot.
2. In the chat, ask: "How is the confirmation going? Which method is winning?" The lead may say how many confirmation
   runs finished, but its reply gives none of their scores and names no winner from them. Open the turn's tool calls:
   none of them shows a confirmation run's score, file or analysis.
3. Ask: "Read the files of one of the confirmation runs and analyse its journal." The lead answers that the run is
   withheld until the confirmation is released.
4. Once the confirmation is released (the app has no button for it yet: the test covers this step), ask the question of
   step 2 again. The lead now reads the runs and answers with their scores.

part's merge commit, compared with the run at the `baseline` tag. Expected: S15 fails at `baseline` and passes here.
