# F1 — A standalone Python project from the charter

State: implemented and tested (PR #__PR__, 2026-10-27); nothing to check live until F2 adds the export.

## What was wrong

- A charter could not leave Balsamic. The coding agent started from a JSON dump of one proposal, and a researcher had no
  way to take the charter to their own tools: write the objective, write a few search functions, run them, compare.

## What changed

| Change | Where |
|---|---|
| `scaffold(charter, revision, *, name=None, charter_id=None)` returns a project's files by path, as bytes. It is pure: the same revision gives the same bytes. It refuses a charter with no objective, no decision variables, or a shape or bound its values cannot resolve | new `problem_charter/scaffold.py` |
| Generated: `pyproject.toml` (the problem id as the name, version 0.1.0, numpy, pytest as the `test` extra, pytest configured to run from the project root), `charter.json` (charter id, revision, content hash, the charter), `README.md` | `scaffold()`, `_pyproject()`, `_readme()` |
| `<pkg>/data.py`: each instance's resolved values (derived quantities computed, the instance's own values applied), its candidate schema (each variable's shape, offset, bounds or values; each linear constraint with its resolved bound), the objective, the tables and the reference results | `_instance()`, `_data()` |
| `<pkg>/problem.py`: a typed `Values` class generated from the quantities, a `Problem` per instance with `is_valid()`, `violations()`, `unpack()`/`pack()`, `random_candidate()`, `table()` | `scaffold_files/problem.py.tmpl`, `_values_class()` |
| `<pkg>/harness.py`: `StopSearch(BaseException)`, `InvalidCandidate`, `@deterministic`, and `run(method, problem, seed, max_seconds=None, max_evaluations=None)` returning the log, the best and the elapsed time; at least one cap is required. A method that computes the objective itself (decision 22) is stopped at `max_seconds` by an alarm | `scaffold_files/harness.py.tmpl` |
| `<pkg>/compare.py`: `python -m <pkg>.compare [--seeds N --seconds S --evaluations M]` ranks every run by the objective's direction with its time and evaluations. The default cap is 10 seconds; a `@deterministic` method runs once whatever `--seeds` says (decision 14) | `scaffold_files/compare.py.tmpl` |
| For the agent to fill: `<pkg>/objective.py` (raises `NotImplementedError`; its docstring is the charter's definition with values filled in, the constraints and the evaluator notes) and `<pkg>/methods.py` (`METHODS = {}`, one example in a comment) | `_objective()`, `scaffold_files/methods.py.tmpl` |
| Generated tests: `tests/test_problem.py` (the data is the charter revision, by hash and by input values; dimensions; `is_valid`; the objective is finite, and repeats when the charter's evaluator is deterministic; each reference result whose `holds_at` gives every decision variable is checked, the others are skipped naming the number) and `tests/test_methods.py` (over `METHODS`: valid candidates, the same run for the same seed, the cap respected) | `scaffold_files/test_*.py.tmpl` |

## Checked

- `tests/test_problem_charter_scaffold.py` (9 tests): golden checks of a continuous charter (the flow reactor) and a
  discrete one with two instances (oven trays): the file list, `pyproject.toml`, `charter.json` and its hash, the
  resolved data and bounds, the objective's docstring; the same bytes twice; names and the charters it refuses; no
  generated file imports `optimization_framework`, `balsamic` or `dqn_meent`; the unfilled project fails only on the
  objective; filled with an objective and three methods, the project passes its own tests in a temporary directory, the
  reference with a candidate is checked and the one without is skipped with its number; `compare` ranks a minimize
  problem with the smallest value first and a maximize one the other way, runs deterministic methods once and the others
  once per seed, and stops a white-box method that never calls `evaluate` on `--seconds`.

## Not done

- Permutation charters: the contract has no permutation representation until C1. The generator refuses any
  representation it does not know, and C1's follow-up adds it here.
- `oracle` problems (decision 22, part N11): the charter has no such flag yet, so every project is white-box and the
  comparison caps time by default.
- The export (F2), the Balsamic glue (F3) and coding workspaces that start from the project (F4).

## Acceptance test

None: F1 adds no screen. It shows to a user with F2, whose "Export as Python project" button on the Charter tab downloads
this project; until then, the tests above are the check.
