# N4 — Pack tools

State: implemented and tested (PR #51, 2026-10-27); the acceptance test is Hoseung's.

## What was wrong

Layer: mandate. A command meant for one problem was offered to agents of every campaign, whatever its problem.
Invariant: INV-N4-1 (new).

`mask_create` (make a full-sized binary test design) was in every agent's base tool set, and `fixed_mask.run` (evaluate
saved designs at several fidelities) was one of the experiment operator's commands, for any problem. Both are MEENT's: a
campaign on `bounded_continuous` or a knapsack was offered a binary mask maker and a fixed-mask evaluator it has no use for.

## What changed

| Change | Where |
|---|---|
| `mask_create`, `fixed_mask.run`, its payload `FixedMaskInput` and its handler `reserve()` move into MEENT's pack, which declares two tool hooks: `register_agent_tools` (the tool, for the same roles as before) and `register_operations` (the command on the workspace's bus, run by the experiment operator, with its compute default and notice wording) | `src/dqn_meent/pack/tools.py`, `src/dqn_meent/pack/__init__.py` |
| A campaign's packs run their tool hooks the first time the campaign's packs are asked for, once per workspace. `packages(campaign_id)` gives the packages of the campaign's packs | `evaluation/packs.py` `CampaignPacks.activate()`, `packages()` |
| `register_tool(..., pack=, local=)`: a pack's tool is offered only to agents of campaigns that have the pack; a local tool's changes commit with its receipt (as `mask_create`'s did). `register_page_operation()`: a pack's command joins its page agent's commands in those campaigns only, and the lead is routed to that agent as for the pages' other work | `agents/tools.py` `PiTools.names()`, `schema()`, `page_work()`, `pack_operations()` |
| `CommandService.register(..., pack=)`: the bus runs a pack's operation only in campaigns that have the pack, the researcher's own commands included, and names the pack when it refuses. An operation it does not know yet has the campaign's packs registered first | `campaigns/commands.py` `execute()`, `_apply()`, `packages()` |
| `compute_consent.declare()`: a pack's operation gives its compute default and how a notice calls it; `fixed_mask.run` is no longer in the core's tables | `campaigns/compute_consent.py` |
| `campaign_inspect`'s capabilities: every agent is told how chosen designs are re-checked on any problem (`validation.run` with a recipe the problem declares); `fixed_mask_diagnostics` appears only in campaigns whose pack adds it, worded as before | `agents/tools.py` `capabilities()` |
| The core keeps the runner of `fixed_mask_job` records (`reconcile()`, the worker), so jobs and reports keep their kinds and earlier campaigns read as before; the activity labels for old receipts stay | `agents/diagnostics.py`, `agents/tools.py` `STEPS`, `COMMAND_STEPS` |

## Checked

- `tests/test_pack_tools.py` (4 tests): in one workspace with a `meent_grating` campaign and a `bounded_continuous` one, the
  MEENT campaign's operator has `mask_create` and `fixed_mask.run` (its commands are exactly the page's plus that one), its
  lead has `mask_create` and is routed to the operator for `fixed_mask.run`, `mask_create` saves a 64-cell `mask` artifact
  with its receipt, and the operator's `fixed_mask.run` reaches the pack's handler; the other campaign's lead and operator
  have neither, even after the MEENT campaign registered them, `mask_create` is refused there, and the researcher's own
  `fixed_mask.run` is refused naming `dqn_meent.pack`; a fresh workspace with no MEENT campaign refuses the command; old
  `fixed_mask_job` and `fixed_mask_report` records in a campaign without the pack are read and found with `evidence_read`
  and `evidence_search`, and their compute still counts against the budget.
- `tests/test_pi_fixed_masks.py` imports `reserve` from the pack; its MEENT test skips without `meent` here, as before.
- `tests/test_page_agents.py` (the page agents' command sets on a `bounded_continuous` campaign) passes unchanged.
- The full suite (counts in the PR).

## Not done

- N1's allowlist does not shrink: the ratchet counts the words meent, rcwa, grating, flrl and deflector, not "mask", and
  none of the files N4 changes was on the list. The roadmap's "Done when" item assumed otherwise.
- The roadmap names `reevaluate:v1` as a generic recipe; it is `meent_grating`'s own. The generic registered recipes are
  `candidate_reevaluation:v1` and `fidelity_comparison:v1`, and a problem offers them only when it declares them, so the
  capability text names "a recipe its problem declares" rather than an id.
- No procedure names the generic recipes: the operator's guidance on this is the capability in `campaign_inspect`, so the
  prompt ratchet is untouched. N3 moves MEENT's procedures into the pack.
- A session's tool list is set when its manifest is read; a task on another problem added to a running campaign shows in
  the next manifest.

## Acceptance test

1. Open a campaign on the 1D grating problem (or the 2D deflector). On the Experiments page, ask the experiment operator:
   "Make a test design that is all zeros and evaluate it at the current fidelity." It makes the design and starts a
   fixed-design evaluation, which appears with the campaign's work as before.
2. Open a campaign on a benchmark problem (the bounded continuous quadratic, or a knapsack). Ask the experiment operator the
   same. It should not make a mask or start a fixed-mask evaluation; it says it has no such tool here and offers to
   re-check designs with a validation the problem supports, or says the problem has none.
3. In the benchmark campaign, ask the lead agent "Which tools do you have for test designs?" It should not list
   `mask_create`.
4. Open an older grating campaign that ran fixed-mask evaluations before this release. Their results still show, and asking
   the lead about them gets the same numbers as before.
