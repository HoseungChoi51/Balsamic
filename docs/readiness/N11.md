# N11 — Access and cost model per problem

State: implemented and tested (PR pending, 2026-10-27); the acceptance test below is Hoseung's.

## What was wrong

Layer: evidence. Every problem was treated as a black-box oracle: a method could not use the objective's code, and a
method that computes the objective itself (dynamic programming, branch and bound, a solver) had no way to do so through
Balsamic. A run on several threads could never be compared with single-thread runs, and nothing said whether a problem's
methods should be judged by evaluations or by time.
Invariant: INV-N11-1, INV-N11-2 (added).

## Checked

- `tests/test_access_and_cost.py` (8 tests): a problem is white-box unless it or its pack says otherwise (both MEENT
  problems are oracle on worker-seconds); a white-box function method that computes the objective 10,000 times and calls
  `evaluate` once reports one observation, its cost row includes its own compute, and the report ranks it on
  worker-seconds; on an oracle task the same kind of method has no `objective`; a two-thread run is compared with a
  one-thread run on core-seconds (its cost twice its wall time) and kept apart on worker-seconds; a manifest dumped before
  N11 parses to the same bytes and reads as oracle, definitions, bindings and setups that declare nothing dump as before,
  and a task stored before N11 freezes its runs as before, with the same experiment-spec digest; a campaign update with
  the same old tasks keeps them; a charter sets the access and the axis, its manifest and task carry them, and its view
  names the problem's own declaration until the charter sets one.
- `frontend/tests/access-cost.spec.ts` (3 Playwright tests): the curve over seconds on a white-box run with the switch to
  evaluations, over core-seconds on two threads, over evaluations on an oracle run; the Charter page's access choice sends
  `evaluator.access`.
- The full suite (counts in the PR).

## Not done

- A method cannot declare its own `threads` yet: a run's thread count is the trial's `numerical_threads`, set when it is
  created. Capping a declared count by the problem's `resources` (every problem says one thread today) would make the
  declaration do nothing, so it waits for a problem that declares more.
- The step budget stays as it is on white-box runs. Raising it to a safety cap by default would turn every quick run of
  the built-in methods into a full wall-time run and mark it censored; time budgets are set per run.
- The adaptive race is MEENT's only (oracle, worker-seconds) and is unchanged. N5 moves its ladder and cost model into the
  pack: its "cost measured by evaluations" should read "by the problem's cost axis" there, and N14 makes the race generic.
- The coding brief's line for oracle problems ("a method must not compute the objective another way") belongs to F4 and
  H4, which write the brief. The exported Python project (F1, F2) is still white-box only: it does not yet read the
  charter's access.
- `analysis/comparison.py` (the legacy grating analysis) is unchanged; it keeps `worker_threads` in its condition on
  every axis and has no core-seconds axis.

## Acceptance test

1. Start the app and open a campaign on an installed benchmark problem (for example the quadratic). Open a run on the
   Experiments page: the Run section says "Objective: white box: the method may compute it itself; judged by its time",
   and the score curve says "over seconds". Press "Show over evaluations": the curve redraws over evaluations.
2. Open a MEENT campaign's run: it says "oracle: reached only through evaluations", and its curve is over evaluations,
   as before.
3. Start a new problem from the problem note and open its Charter page before confirming. "How methods reach the
   objective" shows "the problem's own: white box" and the comparison axis. Choose "oracle" and confirm the charter: a
   run on that campaign then says "oracle".
4. On a MEENT campaign's Charter page the same section shows "the problem's own: oracle" and "worker-seconds".
