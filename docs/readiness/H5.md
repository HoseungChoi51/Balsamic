# H5 — Walls in code

State: implemented and tested (PR pending, 2026-10-27); merges after the `baseline` tag. The live check is Hoseung's.

## What was wrong

- **The public internet was open from the coding box.** `network.sh` refused private, link-local and CGNAT ranges and new
  IPv6 connections, and accepted every other address.
- **The limits were fixed** at `--cpus 4 --memory 8g` for every workspace, and nothing the researcher set bounded them.
- **There was no deadline.** A workspace ran until someone stopped it, and its instructions said so ("This session has no
  programming wall-clock deadline").
- **Nothing said the one-provider credential was the only secret in the box.**

## What changed

| Change | Where |
|---|---|
| An egress allowlist (decision 18): the container is started with `EGRESS_HOSTS`; `network.sh` resolves each host at start and accepts only those addresses and DNS to the resolver, then rejects everything else. Private ranges are rejected before the allowlist, so an allowed host on a private address stays unreachable; no list means nothing public | `deploy/implementation-workspace/network.sh` |
| The list is on the workspace record (`egress`: `model`, `package_index`, `named`): the model's endpoint (a custom provider's `baseUrl`, or the known hosts of a provider Pi has built in), the package index (pypi.org and files.pythonhosted.org, or the host of `GRATING_PACKAGE_INDEX_URL`) and the hosts the request names. A provider whose host is unknown is refused unless its host is named. A workspace recorded before gets its model's and the index's | `agents/development_runtime.py` `egress()`, `model_hosts()`, `allowed_hosts()`; `agents/development.py` `walls()` |
| A request may name more hosts (`egress_hosts`, lowercase DNS names). An agent's must be in its go-ahead: a compute request gains `egress_hosts` (only with `coding_workspaces`), the approval card lists them, and the consent keeps them | `contracts/commands.py` `ApprovalRequestInput`; `campaigns/commands.py`; `campaigns/compute_consent.py` `grant()` |
| A wall-clock deadline per workspace: `wall_seconds` (an agent's defaults to its go-ahead's wall time and may not exceed it), running from the box's first start (`deadline_at`). At the deadline the workspace is paused, not removed; its phase, activity, latest checkpoint and tests are recorded (`deadline_reached`); one `deadline_reached` event and one notice go to whoever opened it; the card shows the error | `agents/development.py` `reach_deadline()`, `_sync_one()` |
| Going on is a new go-ahead: past the deadline, a resume needs `wall_seconds` (how long from now). The card offers "Let it go on for 1/2/4/8 h" | `agents/development.py` `WorkspaceControl`, `control()`; `frontend/src/hypotheses/Implementations.tsx` `GoOn` |
| Running wall time is counted on the workspace (`usage.wall_seconds`) and charged to the go-ahead it opened under (`used_wall_seconds`; the mandate after R3) | `agents/development.py` `charge_wall()` |
| Limits come from the request (`limits`: `cpus`, `memory_gb`, `gpus`), within the researcher's ceilings: the launcher's `development_max_cpus`, `development_max_memory_gb`, `development_max_gpus` (defaults 4, 8 and 0). No GPU unless named and allowed. Without limits, today's 4 CPUs and 8 GB, lowered to the ceilings | `agents/development.py` `WorkspaceLimits`, `walls()`; `agents/development_runtime.py` `ceilings()`, `limit_args()`; `scripts/manage_servers.py` |
| The lead's `implementation_workspace_create` takes `wall_seconds`, `limits` and `egress_hosts` (H4's ticket will carry them) | `agents/tools.py` |
| The card shows the deadline, the limits and the only hosts the box can reach; the timeline shows "Deadline reached: paused" | `frontend/src/hypotheses/Implementations.tsx` `walls()`; `agents/development_timeline.py` |
| The coding agent's instructions say what the network reaches and that the workspace pauses at its deadline (the same length as before) | `agents/development.py` `DEVELOPMENT_INSTRUCTIONS` |
| The one-provider credential is documented as the only secret in the box, for any harness added later too | `docs/pi-agent-harness.md`; INV-H5-2 |
| INV-24 now covers the allowlist; INV-25 (the deadline) is `code`; new rows INV-H5-1 (limits within ceilings) and INV-H5-2 (one secret) | `docs/invariants.md`; `tests/test_invariants.py` anchors the deadline's function instead of "| H5 |" |

## Checked

- `tests/test_invariant_pins.py::test_the_coding_box_reaches_only_its_allowed_hosts_and_dns`: `network.sh` run against
  stub `iptables` and `getent`; the generated chain accepts the allowed hosts' addresses and DNS to the resolver, and
  rejects another public host, the resolver on another port, private and CGNAT addresses, an allowed host that resolves to
  a private address, and everything public when no host is listed.
- `tests/test_pi_development_workspaces.py`: the allowlist is on the record and the view, a URL is refused as a host, a
  mirror replaces PyPI, and the container is started with every allowed host and the record's limits (old records get
  4 CPUs, 8 GB, no GPU); limits above the ceilings, and any GPU by default, are refused before anything is recorded;
  an agent's deadline past its go-ahead's wall time, or a host the go-ahead did not approve, is refused; a workspace past
  its deadline is paused with its last checkpoint kept, the lead is told once, its wall time is charged to the go-ahead,
  and a resume without a new `wall_seconds` is refused; a provider with an unknown host needs it named.
- `tests/test_compute_consent.py`: a compute request's `egress_hosts` need coding workspaces and DNS names, appear on the
  approval card and are kept on the consent.
- `tests/test_server_launcher.py`: the ceilings reach the services, are checked, and one left in the shell is not passed on.
- `frontend/tests/implementations.spec.ts`: the card shows the deadline, the limits and the hosts; a workspace past its
  deadline shows the error and resumes for the chosen hours.
- Full runs at the PR's head: see the PR.

## Not done

- A network-namespace test of the real rules (iptables in a container): the CI has no Docker. The live check covers it.
- Addresses are resolved when the container starts. A host whose addresses rotate (a CDN) can become unreachable in a
  long-running box; restarting the workspace resolves again. Unpausing does not.
- The known hosts of Pi's built-in providers are a list in `development_runtime.PROVIDER_HOSTS`; a provider missing from
  it needs its host named.
- Containers created before this change keep their old network and limits until they are recreated (removed and opened
  again), and then get their model's host and the package index.
- The ticket (H4) will carry `wall_seconds`, `limits` and `egress_hosts`; until then the request carries them. The
  mandate (R3) will replace the consent as what the wall time is charged to.

## Acceptance test

Use a lab with coding workspaces switched on (the workspace image rebuilt from this release) and a campaign whose lead
agent is on.

1. Ask the lead for a coding workspace for one proposal, and approve the go-ahead it asks for. Open
   **Proposals → Implementations**. The workspace's card should show a **Deadline** row (the go-ahead's time from when it
   started, with "pauses then, in …"), a **Limits** row ("4 CPUs · 8 GB memory · no GPU") and a **Network** row naming
   only the model's host, pypi.org and files.pythonhosted.org.
2. Open the editor from the card and, in its terminal, install a package (`pip install --user rich`). It should install.
   The coding agent should also keep working, which shows it reaches its model.
3. In the same terminal, try to reach another site (`curl -I https://example.com`). It should be refused at once.
4. Ask the lead for a workspace that needs another site (for example "clone the reference code from github.com"). The
   approval card should say its coding workspaces may also reach github.com. Approve it; the new card's Network row
   should list github.com as approved, and `curl -I https://github.com` from its terminal should work.
5. Ask for a short go-ahead (about 10 minutes) for another workspace, and wait past it. The card should turn to paused
   with "reached its deadline" in red, the history should show "Deadline reached: paused" with the agent's last
   checkpoint, and the lead should tell you once in the chat. Choose 1 h in "Let it go on for" and press **Resume**: the
   card should show a new deadline an hour away, and the coding agent should carry on where it stopped.
