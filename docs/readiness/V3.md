# V3 — A fidelity check before finalist and library

State: implemented and tested (PR pending, 2026-10-27); not checked live (see the acceptance test).

## What was wrong

- **A score that collapses at higher fidelity could be promoted.** Readiness Part F found a 2D deflector design that
  scored 93.75% at RCWA orders (10, 5) and 67.56% at (26, 22). Nothing tied that check to a decision: a strategy became a
  finalist after an implementation-readiness check only (`hypothesis.nominate`, `hypothesis.status` finalist), a
  shortlist (`finalist.set`) took any finished run, and `library.publish` took any finalist with its best score as
  measured.
- **The check existed but bound nothing.** The 2D MEENT problem has an order-convergence recipe
  (`meent_2d_order_convergence:v1`, half a point at the two highest orders) and the validation records (requirements,
  results, waivers) to hold its outcome; the procedure `rcwa-convergence-check` was prose.

## Checked

- `tests/test_promotion_fidelity.py` (7 tests):
  - the 2D problem declares its order recipe, and Part F's numbers (93.75% at (10, 5), 67.56% at (26, 22)) fail its
    tolerance through the problem's own `summarize_recipe()`;
  - an agent cannot make a 2D strategy a finalist when its best score was not checked (the refusal names
    `validation.run`, the run and the waiver request) or failed the check, and the researcher cannot publish it either;
    once a check passes, the agent's nomination goes through and the library entry records the validation result id;
  - an agent's waiver of the check is refused; the researcher's waiver opens the gate for nomination and publishing;
  - the researcher's own finalist (by status, or created as one) passes with the warning recorded; an agent creating a
    finalist with no run is refused;
  - a `bounded_continuous` strategy is not gated (`not_required`);
  - the best run follows the objective's direction;
  - a researcher's shortlist records each run's fidelity, with a warning when a declared check never ran; an agent's
    would be refused.
- The existing library, finalist and invariant tests pass: `tests/balsamic/test_library.py`,
  `tests/test_framework_finalists.py`, `tests/test_invariants.py`; Playwright `library.spec.ts` checks the Fidelity row.
- Full suite (see the PR for counts).

## Not done

- **The gate on the pages (V5).** A refused transition and the warning on a researcher's finalist are in the records and
  the command's error, not yet on the evolution page or the proposal card; there is no one-click waiver, and publishing
  a strategy whose check never ran needs the requirement created first (`validation.require`) and then waived.
- **Only the 2D deflector declares a check.** The 1D grating problem (`meent_grating`) and libraries the coding agent
  writes (`EvaluatorManifest`) declare none; problem packs (N2, N3) are where more problems would declare theirs.
- A check counts only with the declared parameters exactly (here `absolute_tolerance` 0.005); a run at a stricter
  tolerance does not count.
- Finalists chosen before this part are not re-checked; their library publishing is checked.
- Until A2 merges, the ledger's "best" (and so the library entry's `best_score`) is the highest score whatever the
  direction; the gate itself already follows the direction, and the entry's `evidence.fidelity.trial_id` names the run it
  checked.
- The live eval S13 (J1's fidelity trap) does not exist yet; it is Hoseung's to run once J1 adds it.

## Acceptance test

Use a 2D deflector campaign (the FLRL 2D problem) with the lead agent switched on and at least two proposals that have
finished runs.

1. In the chat, ask the lead to make one of those proposals a finalist before any higher-order check has run on it. The
   lead says it cannot yet: the order-convergence check has not been run on its best score, and it offers to run the
   check or to ask you for a waiver. The proposal does not show as a finalist on the Evolution page.
2. Ask the lead to run the check on that proposal. When it finishes, ask again for the finalist:
   - if the score held (within half a point at the two highest orders), the proposal becomes a finalist;
   - if it dropped, the lead still cannot make it a finalist and says the score does not hold at higher fidelity.
3. For a proposal whose check failed, let the lead ask you for a waiver. An approval card appears in the Inbox; approve
   it with a reason. The lead can now make it a finalist.
4. On the Library page, publish a finalist whose check passed: the new entry's Fidelity row says "passed" with the
   check's name and its result. Publish the waived one: it says "waived by the researcher". Try to publish a finalist you
   chose yourself without any check: an error says the best score needs the fidelity check or your waiver.
5. On the Evolution page, use "Promote to finalist" yourself on a proposal whose check has not run: it goes through, as
   before (the warning is recorded; the page shows it with V5).
6. In a campaign of another problem (for example the bounded continuous test problem), finalists and publishing work as
   before, and the library entry's Fidelity row says "not required for this problem".
