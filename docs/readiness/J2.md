# J2 — A second problem and a second model

State: implemented and tested (PR #42, 2026-10-27); the live baselines are Hoseung's.

## What was wrong

Layer: none: this part fixes no failure; it widens what the evals measure.
Invariant: none: the register is unchanged (no guarantee moves state; the new presets measure the existing `prompt` rows on more problems).

- Every lead-eval scenario ran on one problem (`quadratic`, or the trap problems of J1), so a lead that behaves only on a
  bounded continuous toy problem passed.
- All 36 passing live runs used one model, and a baseline file was named by its commit only, so a second model's run of
  the same commit would have overwritten the first, and `--compare` read one baseline.

## What changed

| Change | Where |
|---|---|
| `--preset <name>` runs every selected scenario on that preset instead of its own. A scenario lists the presets it supports in `presets` (default: only its `setup.preset`); the others are not run, and `summary.md` lists them under "Not run on <preset>" with the reason (`supports quadratic, deflector_2d, not reactor`) | `scripts/run_lead_evals.py` `supported_presets()`, `main()`, `summary_markdown()` |
| Preset `deflector_2d`: the installed 2D beam deflector's example (`flrl_2d_deflector_1050nm_75deg`), its instances as the tasks, read from the installed examples as the New campaign page does; experiments capped at 60 s (`delegated_trial_seconds`) | `scripts/run_lead_evals.py` `PRESETS`, `campaign_preset()` |
| Preset `reactor`: the flow-reactor charter (a declared evaluator, from chemistry), created and confirmed, and the campaign made from the confirmed revision | `evals/lead/charters/flow-reactor.json` (the charter of `tests/test_problem_charter.py` `reactor()`), `campaign_preset()` |
| Scenarios S1, S2, S9 and S10 support `quadratic`, `deflector_2d` and `reactor`; S3, S4 and S11 (they need an installed evaluator) `quadratic` and `deflector_2d`; the others, whose seeds are written for one problem or which need the gate closed, stay on their own | `evals/lead/scenarios/*.json` `presets` |
| Each run records its preset and the problems its campaign got; the transcript says `- Preset: deflector_2d (meent_2d_dual_polarization_deflector)` | `run_scenario()`, `transcript()` |
| Baselines are named by what they measured: `baselines/<commit>-<provider>-<model>[-<preset>].json`, the model being `--model` or the dev profile's default (`profile_model()`); a scripted run is `<commit>-fake`. The record carries `model_id` and `preset` | `baseline_path()`, `baseline_record()` |
| `--compare` takes several baseline files, one column each, headed by commit · model · preset, regressions marked per column. `a7e89b8.json`, which names no model, reads as "profile default" | `baseline_label()`, `summary_markdown()` |
| The presets, the `presets` field, the file names and the approval rule for a second model documented | `evals/lead/README.md` |

## Checked

- `tests/test_lead_evals.py::test_a_preset_runs_the_scenarios_that_support_it_on_another_problem_and_names_the_rest`: every
  scenario's `presets` are known presets and include its own; `--fake --preset reactor --scenarios S2,S3,S6` runs S2 on a
  campaign whose task is `flow_reactor_yield` and passes, and lists S3 and S6 as not run with their reasons in
  `results.json` and `summary.md`; `--preset deflector_2d` runs S3 on `meent_2d_dual_polarization_deflector` and passes;
  without `--preset` a scenario runs on its own preset as before.
- `tests/test_lead_evals.py::test_a_baseline_is_named_by_its_model_and_preset_and_several_compare`: the file names for the
  default model, a model with an effort and a preset, and a scripted run; the profile's default is read; two baselines
  give two labelled columns, the regression marked only against the one that passed; `--compare a.json b.json` on the
  command line.
- By hand, `--fake --preset deflector_2d` and `--fake --preset reactor` with S1, S2, S3, S4, S9 and S10: every supported
  scenario passes on the scripted harness.
- The whole fake suite (the existing test) still passes with every scenario on its own preset.
- Full suite with `-n 4`: 1054 passed, 96 skipped; the one failure was the known isolated-host flake. The launcher's 17 tests pass as `claude`.

## Not done

- No live baseline is recorded: it calls a model, and live evals are Hoseung's (below). "Done when" asks for baselines
  of `quadratic` and `deflector_2d` on the default model, and on a second model once approved.
- `deflector_2d` needs MEENT for any run (S11 on it, and S3/S4 if the lead starts one); the cloud cannot install MEENT,
  so the scripted runs check only S1–S4, S9 and S10 there, which start nothing.
- `reactor` is a declared problem (no evaluator). Once Phase 1's E track lets a small library provide it, the preset
  should take its problem from that library (roadmap J2 item 3); today nothing can run on it, by design.
- The trap scenarios (S12–S15, S17) stay on their own problems: their seeds are written for them.

## Acceptance test

None in the app: this part changes the eval runner, not anything a researcher sees. It shows in the eval output, which
Hoseung runs live (the dev stack's keys in `~/.config/balsamic/secrets.env`, MEENT installed for the deflector):

1. The default model on the two problems (Centinels, no approval needed; each scenario is capped at $0.30–0.50):

   ```bash
   uv run python scripts/run_lead_evals.py --preset quadratic --record-baseline
   uv run python scripts/run_lead_evals.py --preset deflector_2d --record-baseline
   ```

   Two files appear in `evals/lead/baselines/`, `<commit>-centinels-gpt-6.1-sol-quadratic.json` and
   `<commit>-centinels-gpt-6.1-sol-deflector_2d.json`. The deflector run's `summary.md` lists S5–S8, S12–S15 and S17 under
   "Not run on deflector_2d", each with a reason; each transcript says `Preset: deflector_2d
   (meent_2d_dual_polarization_deflector)`. Commit both files.
2. Optionally the reactor: `--preset reactor --record-baseline`. A good lead says no run can start (the evaluator is
   declared, not installed) rather than trying.
3. A second model, only with Hoseung's approval when it is another provider (a second Centinels model needs none):

   ```bash
   uv run python scripts/run_lead_evals.py --preset quadratic --model <provider>/<model> --record-baseline
   ```

   Then compare the two models in one table:
   `--compare evals/lead/baselines/<commit>-centinels-gpt-6.1-sol-quadratic.json evals/lead/baselines/<commit>-<provider>-<model>-quadratic.json`.
   `summary.md` has a column per file; a scenario that passed in one and fails now is marked **regressed** in that column.
