# E1 — The problem registry picks up installs

State: implemented and tested (PR #13, 2026-10-27); nothing for a user to see until E2 lets the installer accept a
problem library.

## What was wrong

- **Problem plug-ins were discovered only at start-up.** `problems = ProblemRegistry().discover()` read the
  `optimization_framework.problems` entry points once, at import. A library that provides a problem, installed while the
  services run, stayed invisible until a restart. Optimizer plug-ins already re-checked installs every second.

## What changed

| Change | Where |
|---|---|
| The installed-package helpers move to a shared module: `pick_up_installs()`, the entry-point and version `snapshot()`, `forget_changed()` (drops a changed package's modules, never the lab's own), `RECHECK_SECONDS` | `installed.py` (new); `optimizers/plugins.py` and `execution/source.py` use it |
| The discovered registry compares the installed entries with what it loaded at most once a second, on `ids()` and `get()`, and updates itself in place: new problems are added; for a changed or removed entry the cached adapter and the package's modules go. The lab's own problems are never dropped, even if their metadata changes | `evaluation/registry.py` `ProblemRegistry.discover()`, `_sync()`, `_recheck()` |
| Registries built with `from_entries()` (frozen hosts) or `extended()` never re-check | `ProblemRegistry` (`_discovered`) |
| New register row: a package installed while the services run is picked up, and the lab's own packages are never dropped by it | `docs/invariants.md` INV-31 |
| The plug-in guide says the problem registry follows installs the same way | `docs/optimizer-plugins.md` "Installed while the lab runs" |

## Checked

- `tests/test_problem_registry_installs.py`: a problem package installed into a temporary site directory (as uv's editable
  install lays it out) is listed after a second and not before, resolves and gives an evaluator; a version bump reloads it
  (a new adapter with the new name); an uninstall drops it and its module; the lab's own `bounded_continuous` keeps the same
  adapter and module when its version appears to change or its entry disappears; a frozen and an extended registry do not
  change; the shared `problems` object picks the install up in place. Four of the five fail on the previous registry.
- `tests/test_optimizer_plugins.py` still passes with the helpers moved.
- Full suite with `-n 4`: 940 passed, 96 skipped; `tests/test_server_launcher.py` as user `claude`: 17 passed.

## Not done

- The installer still refuses a library with no optimizer entry point, and records no `problems_added`: that is E2.
- An id clash between an installed problem and one already loaded is not refused here: the first loaded keeps the name
  until it is uninstalled. E2 refuses clashes at install.

## Acceptance test

None: nothing a user can do reaches it yet, because the installer accepts a problem library only from E2. It shows in
the tests above; the phase's acceptance test for E2 (install a library that provides a problem, and see the problem listed
without restarting Balsamic) covers it from the app.
