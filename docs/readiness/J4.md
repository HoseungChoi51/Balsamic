# J4 — A coding eval

State: implemented and tested with the scripted agents and a prepared library (PR #23, 2026-10-27); the live baseline is
Hoseung's to record.

## What was wrong

- **Nothing measured the coding path.** How long a coding workspace takes to build a method from its proposal, what it
  costs, how much the implementation lead has to relay, and whether the result passes the contract were known only from
  the 2d-gratnig campaign's history. Phase 4 changes that path (the coding box) and had no number to beat.

## What changed

| Change | Where |
|---|---|
| Three scenarios, one per method of `libraries/grating-mask-search`: the proposal as a researcher wrote it (verbatim from H12's and H13's specifications; H14's written from its module, its mechanism not being in the repository), the researcher's request to the implementation lead, and the files withheld (the method's module, tests and specification) | `evals/coding/scenarios/C1–C3` |
| The runner: a source repository without the method (no history, the method dropped from `plugin.py`), a lab on a temporary directory with workspaces on and installing off, the request through the implementation lead, the researcher's go-ahead and answers while it waits, then the delivery checked outside the box: its `tests/test_contract.py` (passing and naming the method) and `conformance.check()` of the method through the library's own entry point | `scripts/run_coding_evals.py` |

## Checked

- `tests/test_coding_evals.py` (8 tests): each method is a scenario whose withheld files exist; `plugin.py` loses exactly
  the one method, for each of the three; the workspace's source is one commit, without the withheld files, and only the
  contract test names the method; that library delivered unchanged fails conformance and its contract test; the original
  library passes both; a contract test that leaves the method out does not count; a delivered path cannot leave the
  directory; a fake run goes through the implementation lead under one approved go-ahead, passes, writes the delivery and
  records a baseline, and a baseline that passed shows a regression.
- `uv run python scripts/run_coding_evals.py --fake`: C1, C2 and C3 pass, each in about 11 s from the request to the
  submission.
- The full suite, in the PR.

## Not done

- **The live baseline.** It needs Docker with the workspace image and a signed-in model provider, which the cloud session
  does not have; it is Hoseung's (below). No baseline file is committed yet.
- The reviewer's read of one diff for quality is by hand: the runner writes the delivered library under
  `delivered/<scenario>/` and grades only the contract and conformance.
- The delivered code runs on the host, in a subprocess, as it would once installed; it is not sandboxed.
- No row of `docs/invariants.md` changes: the part adds a measurement, not a guarantee.

## Acceptance test

None in the app: J4 adds an eval and changes nothing a researcher sees. Its live check is the baseline, a live eval:

1. On the machine that runs the lab, with Docker, the workspace image and the harness built, at the commit that merges
   this part (or the Phase 2 release tag): `uv run python scripts/run_coding_evals.py --scenarios C1 --record-baseline`.
   It runs on the dev profile's default provider (Centinels), so it needs no approval, and takes up to four hours.
2. Expect `C1-cyclic-geometric-vnd: pass` or `fail`, a `summary.md` with the time to the submission, the model dollars,
   the turns, the relayed messages, the contract and conformance, and `evals/coding/baselines/<commit>.json`. Either
   outcome is a baseline; a run that times out or errors before the workspace opens is not, and is worth reporting.
3. Read `runs/coding-evals/<timestamp>/delivered/C1-cyclic-geometric-vnd/` against
   `libraries/grating-mask-search/src/grating_mask_search/cyclic_geometric_vnd.py` for quality, and commit the baseline file.
