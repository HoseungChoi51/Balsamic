# D1 — `FunctionMethod`: a function becomes a method

State: implemented and tested (PR pending, 2026-10-27); not live: a function method reaches the lab once D2 lists a
library's functions, and the live check is Hoseung's after F3.

## What was wrong

A method had to speak the optimizer_v1 contract: propose, observe, checkpoint, restore, inspect, export. For a few lines
of search (a greedy order, a random restart, a small enumeration) that is most of the code, and it is where a coding agent
gets a method wrong.

## What changed

| Change | Where |
|---|---|
| A method is a function `def <method_id>(problem, evaluate, rng)`. `evaluate(candidate)` returns the primary objective in the charter's units and direction, raises `ValueError` for a candidate that was not evaluated (invalid, or the evaluation failed) and `StopSearch` once the run is over. Returning finishes the method (`method_finished`, A3); a returned string is its reason | `optimizers/functions.py` (new) |
| `StopSearch` derives from `BaseException`, so a method's `except Exception` cannot swallow it | `optimizers/functions.py` |
| `FunctionMethod(fn, instance, parameters, seed, *, problem=None)` runs the function in a daemon thread and gives the worker one proposal per `evaluate` and its observation back; the function's own exception fails the run with its message | `optimizers/functions.py` |
| `rng` is `numpy.random.default_rng(seed)`; `random` and `np.random` are seeded with the same seed when the function starts | `optimizers/functions.py` |
| `problem` is the library's own problem object when one is passed (F3 passes it), else a read-only view of `instance.descriptor()` (mappings and lists frozen all the way down) | `optimizers/functions.py` `frozen()` |
| The checkpoint is `{"contract": "function_v1", "seed", "log": [[candidate_hash, status, score], …]}` (a candidate that was not evaluated keeps its error as a fourth item). `restore()` runs the function again from the start and answers `evaluate` from the log, checking each candidate's hash; a mismatch fails the run as "not deterministic for its seed". After the log it continues live | `optimizers/functions.py` |
| `close()` makes the next (or the waiting) `evaluate` raise `StopSearch` and gives the thread 5 seconds to end. One live function method per process: a second is refused while the first is open or its thread is running (the global seeds are per process; each trial's worker is a process of its own) | `optimizers/functions.py` |

The worker needed no change: its evaluation cap, wall cap, pause and stop end the loop before the next `propose`, and its
`close()` of the optimizer ends the function.

## Checked

- `tests/test_function_methods.py` (11 tests): a one-shot method (three evaluations, then returns) completes as
  `method_finished` with its best; a returned string is the finish reason; an endless method is stopped by the
  evaluation cap and by the wall cap, and its thread ends; a method that wraps `evaluate` in `except Exception` still
  stops; a method that raises `ValueError` fails with its message; an invalid candidate is a `ValueError` the method can
  catch and go on; a run paused after three evaluations and resumed records the same six candidates as an uninterrupted
  run with the same seed, and its replayed log equals the paused one; a method whose candidates read the clock is refused
  on resume, with no new request; the problem view is read-only, and a second live method in a process is refused.
- `tests/test_method_finish.py` still passes beside it. The full suite in parallel: see the PR.

## Not done

- No library can offer a function method yet: listing a library's functions without importing them, function
  conformance and `PYTHONHASHSEED=0` for workers are D2. Until then a `FunctionMethod` runs when it is handed to the
  worker, as the tests do.
- The library's own problem object (with `problem.objective(candidate)` on a white-box problem) comes with F3; without
  one, the method sees the descriptor and calls only `evaluate`. The `oracle` case is N11.
- The wall cap is checked between evaluations, as for every method: a function that computes for a long time without
  calling `evaluate` is stopped by the study's absolute deadline (the watchdog), not by `wall_seconds`.
- Resuming costs the method's own compute again up to its checkpoint (the replay), as the roadmap's risks say.
- `docs/optimizer-plugins.md` gains "Plain-function methods" in D2, with the plug-in that offers them.

## Acceptance test

None: nothing a researcher sees changes until D2 lets a library offer its functions as methods and F3 generates such a
library from the charter. The change shows in `tests/test_function_methods.py`; Phase 1's acceptance test (after F4)
covers it end to end, when a library's plain functions appear as methods and run.
