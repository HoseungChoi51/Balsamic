# H8 — One implementation route

State: implemented and tested (PR pending, 2026-10-27; `main` with H1–H7 merged); the acceptance test on a live lab is Hoseung's.

## What was wrong

Layer: evidence. Code could still enter the lab on a route other than a coding box's library validated outside the box: the
implementation library's own agent loop, judged by what its own roles said.
Invariant: INV-H8-1, INV-H8-2, INV-H8-3, INV-H8-4 (added); INV-H7-1 (updated).

- **Two routes still built code after H7.** The implementation service kept its agent loop: a builder, a test designer that
  froze checks and a model reviewer, run as Pi agents of an implementation grant with restricted file tools and a 30 s Python
  runner. It served a commission while coding workspaces were off, one that imported a package, and an evaluator for a task no
  charter declares; and a coding workspace could still send its submission to it (`implementation_workspace_validate`, with
  frozen envelopes), beside H6's validation outside the box.
- **Three role sets and two instruction texts.** `ROLES`, the tool set, the harness and the tiers page carried the grant roles,
  and `GRANT_INSTRUCTIONS` kept their pre-plan text.

- The full Python suite, the lead evals (`--fake`), the coding evals' test, the harness suite, the frontend type check and the
  Models page's browser test pass (counts in the PR).

## Not done

- **A package import through the workspace.** A commission no longer imports a package. Code the researcher already has comes
  in through their own coding agent (H3) or as reference code for a workspace; the library's own API still checks and publishes a
  package, but nothing in the workspace sends one there (the attach commands bind a version it published).
- **An evaluator for a task no charter declares** has no build route: nothing has such a task adopt an installed problem
  (`campaign.adopt_problem` needs a charter), so it is refused and the researcher attaches a validated version.
- `scripts/check_revalidation_restart.py`, a live check that commissions a build first, now gets the refusal; it was not rewritten.
- As H7 left them: a commission's `max_calls` and `api_budget_usd` are recorded on its box, not enforced; `implementation.control`
  reaches grants recorded before, not a box; the specification's behaviour, mechanism and diagnostic checks are not run as
  protected tests.

## Acceptance test

Before: restart the lab, as for any change.

1. Open **Models**: the role list has no implementation builder, test designer or validator.
2. In a campaign whose implementation lead has commissioned something before this change (or any campaign with an implementation
   history), open **Proposals → Implementations**: the old jobs and versions are still listed as they were, with their results.
3. With coding workspaces off, ask the implementation lead to commission an implementation of a proposal. It answers that coding
   workspaces are off and tells you the switch that turns them on (`development_enabled` in the launcher file, then a restart);
   no job appears on the Implementations page.
4. Ask it to commission one that imports code you paste. It answers that a commission builds in a coding box and imports no
   package, and offers your own coding agent (the workspace card's "Deliver from your own coding agent") or a coding workspace
   with the code as reference.
5. With coding workspaces on, the commission of step 3 opens a card under **Coding workspaces**, as in H7's acceptance test.
