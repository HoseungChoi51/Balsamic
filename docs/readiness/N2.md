# N2 — The pack manifest and its loader

State: implemented and tested (PR pending, 2026-10-27); nothing to check live until N3–N8 fill MEENT's pack.

## What was wrong

A problem plug-in could declare its evaluator and nothing else. What MEENT brings besides it (its procedures, the mask
tools, the RCWA memory planner, the race's fidelity ladder, the FLRL reference, the hooks for old records) sat in the core,
offered to every campaign whatever its problem, because there was nowhere for the problem to say "this is mine".

## What changed

| Change | Where |
|---|---|
| `ProblemPack`: the package it lives in, the problem ids it serves, `tools` (hooks that register agent tools and command operations), `procedures` (a folder of `SKILL.md` procedures), `estimators` (memory and time hooks), `racing` (fidelity ladder, limit, cost model, preferred methods), `presentation` (labels and defaults beside `ProblemDefinition.renderer`), `references` (material for coding workspaces: a folder in the package, or one an environment variable names) and `legacy` (hooks for old records). Hooks are `module:attribute`, folders are inside the package; the contract refuses any other form | `contracts/packs.py` |
| An adapter may define `pack()` (decision 17). `ProblemRegistry.pack(id)` and `packs()` collect them from the installed problems, and refuse, naming the problem, a pack that is not for that problem, lives in a package that is not installed, or names a module or folder that is not there. A problem without the hook has no pack | `evaluation/registry.py` `checked_pack()`, `ProblemRegistry.pack()`, `packs()` |
| `workspace.packs.for_campaign(campaign_id)` gives the packs of the campaign's current tasks, each once; a task on a generated evaluator or an uninstalled problem brings none. It asks the registry each time, so problems E1's reload picks up count without a restart | `evaluation/packs.py` `CampaignPacks`, `execution/service.py` `Workspace.__init__` |
| MEENT's pack: `src/dqn_meent/pack/`, shared by `meent_grating` and `meent_2d_dual_polarization_deflector`, and empty for now. `optimization_benchmarks` declares none | `src/dqn_meent/pack/__init__.py`, `src/dqn_meent/problem.py`, `src/dqn_meent/problem_2d.py` |
| Invariant `INV-N2-1` (a campaign gets its own problems' packs only; a broken pack is refused at load) | `docs/invariants.md` |

## Checked

- `tests/test_problem_packs.py` (18 tests): a fake problem with a pack is listed and `bounded_continuous` is not; both MEENT
  problems return the same pack from `dqn_meent.pack`; a campaign with two tasks on the packed problem and one on
  `bounded_continuous` gets the pack once, and a campaign on `bounded_continuous` alone gets none; a pack naming a missing
  module (tools or legacy hook), a missing procedures or reference folder, an uninstalled package or another problem is
  refused with "Problem 'packed_quadratic'" and what is missing, by `pack()` and by `packs()`; a reference given only by an
  environment variable is not checked at load; malformed manifests (no problem ids, a folder outside the package, a hook
  without `module:attribute`, a reference with neither folder nor variable, a repeated id, an unknown field) are refused.
- The full suite (counts in the PR).

## Not done

- Nothing uses a pack yet. N3 (procedures and presentation), N4 (tools), N5 (estimators and racing), N6 (references) and
  N7 (legacy hooks) move MEENT's pieces into `src/dqn_meent/pack/` and make the core read them; N11 adds a `cost` section.
- The pack's `racing.ladder` and `limit` are free-form fidelity dictionaries; N5 may tighten them when it moves the race's
  ladder.
- E1 (the registry picks up installs) has not merged; packs follow whatever problems the registry holds, so they need no
  change when it does.

## Acceptance test

None: the part adds the place where a problem declares what it brings, and MEENT's pack is still empty, so nothing in the
app changes. A MEENT campaign and a `bounded_continuous` campaign should look and behave exactly as before. The change
shows in `tests/test_problem_packs.py`; the first visible effect comes with N3, when MEENT's procedures appear only in
MEENT campaigns.
