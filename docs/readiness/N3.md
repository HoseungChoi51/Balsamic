# N3 — Pack procedures and presentation

State: implemented and tested (2026-10-27); the acceptance test below is Hoseung's.

## What was wrong

MEENT's two procedures, `meent-problem-setup` and `rcwa-convergence-check`, sat among the service layer's generic ones in
`src/balsamic/procedures/`, so every role catalog listed them and `procedure_read` served them in any campaign, a quadratic
benchmark included. And a design's cells were labelled "silicon" and "air" for any problem whose id started with `meent`,
read from the id rather than declared by the problem.

## What changed

| Change | Where |
|---|---|
| The two procedures moved, unchanged, into MEENT's pack; their status stays draft until Hoseung reviews them. The pack declares `procedures="procedures"` and the labels `on_label: silicon`, `off_label: air` | `src/dqn_meent/pack/procedures/`, `src/dqn_meent/pack/n3_procedures.py` |
| `workspace.packs.procedure_folders(campaign_id)`: the procedure folders of the campaign's packs, inside their installed packages | `evaluation/packs.py` |

## Checked

- `tests/test_procedures.py`: the generic catalog no longer holds the two; in a MEENT campaign the lead's static
  instructions do not name them, its state block lists both, and `procedure_read` serves both; an empirical assessor
  delegated there is told of `rcwa-convergence-check` in its state block and can read it; in the `bounded_continuous`
  campaign of the same lab the lead's state block lists neither, `procedure_read` refuses both, and a delegated empirical
  assessor's state block stays empty; a pack procedure named like a generic one is refused.
- `tests/test_experiment_rules.py`: the 2D deflector gets `silicon`/`air` from its pack; the same grid under an id that
  starts with `meent` but is not installed, and under `bounded_continuous`, gets `1`/`0`.
- The prompt ratchet (`tests/test_harness_contract.py`) passes: the lead's instructions went from 964 to 930 words in the
  test campaign; a specialist's stayed at 406 (neither MEENT procedure was in its catalog).
- `tests/balsamic/test_layering.py` passes with the shorter allowlist; `tests/test_invariants.py` passes.
- The full suite (counts in the PR).

## Not done

- Roles that had the MEENT procedures in their static catalog and have no state block of their own beyond these lines
  (the results analyst, the empirical assessor) see them only in an assignment of a MEENT campaign; that is the point.
- The pack's `presentation.defaults` is not read yet; nothing needed one.
- `procedure_hint` names generic procedures only; no tool or command starts a MEENT-only workflow yet (N4 moves the mask
  tools).
- `docs/roadmap/phase-5-evidence-gates.md` still points at the old path of `rcwa-convergence-check`; roadmap files are left
  as they are (README §0.13), and V3 will find it in the pack.

## Acceptance test

1. Start the app and open a campaign on a MEENT grating problem (for example the 2D dual-polarization deflector), or
   create one.
2. In the lead's chat, ask: "Which procedures do you have for this problem? Read the RCWA convergence check and tell me
   its first step." The lead should name `meent-problem-setup` and `rcwa-convergence-check` and summarise the convergence
   check it read.
3. Open or create a campaign on the `bounded_continuous` benchmark problem and ask the lead the same question. It should
   not list either MEENT procedure, and if asked to read `rcwa-convergence-check` it should say there is no such
   procedure for this campaign.

The silicon/air labels are not shown in the app's pages today (they travel in the presentation the experiment rules
hold); they show in `tests/test_experiment_rules.py`.
