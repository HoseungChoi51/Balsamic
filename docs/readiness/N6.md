# N6 — Pack references for coding workspaces

State: implemented and tested (PR #47, 2026-10-27); the live check is Hoseung's.

## What was wrong

Layer: evidence. Every coding workspace got a copy of the FLRL authors' repository (from `GRATING_FLRL_REFERENCE` or a
`../flrl` checkout), whatever the campaign's problem, and every brief told the coding agent that `/references/flrl` held
"the author's reference code". A workspace building a method for a scheduling or quadratic problem was pointed at grating
code that has nothing to do with it.
Invariant: INV-N6-1 (added).

## What changed

| Change | Where |
|---|---|
| A pack reference may name a `default` (an absolute path used when its environment variable is unset) and a `description` (what the brief says it is). A default without an environment variable, or a relative one, is refused | `contracts/packs.py` `PackReference` |
| MEENT's pack names the FLRL repository: `GRATING_FLRL_REFERENCE`, else the `flrl` checkout beside this repository, as before | `src/dqn_meent/pack/__init__.py` |
| `reference_source()` finds a reference on the host (the variable's folder, else the default, else the folder in the pack's package) or reports it absent; `CampaignPacks.references(campaign_id)` gives the present references of the campaign's packs, each name once | `evaluation/packs.py` |
| Opening a workspace asks the campaign's packs for their references, copies each into the read-only `/references/<name>` (a Git checkout's committed tree with `<name>.commit` beside it, as the FLRL copy did; a package folder as it is), and appends a "References" section to the brief naming exactly what was mounted. The hard-coded FLRL copy and the brief's fixed `/references/flrl` and paper sentence are gone | `agents/development_runtime.py` `copy_reference()`, `DockerWorkspace.prepare()`; `agents/development.py` `_sync_one()`, `references_brief()` |
| The researcher's paper (`GRATING_PAPER_REFERENCE`, the launcher's `paper_reference`) is still mounted for every campaign, since it is the researcher's material, not a problem's; the brief now names it only when one is configured | `agents/development_runtime.py` `paper_reference()` |
| The server-control page and the README say the FLRL reference is for MEENT campaigns only | `docs/server-control.md`, `README.md` |

## Checked

- `tests/test_pack_references.py` (12 tests): MEENT's pack names `flrl` and `bounded_continuous` has no pack; a MEENT
  campaign's workspace is handed `flrl` from `GRATING_FLRL_REFERENCE` and its brief names `/references/flrl`; a
  `bounded_continuous` workspace is handed nothing and its brief names no `/references` and no FLRL; a MEENT workspace
  without the checkout gets none and its brief names none; the paper line appears only with a paper; `prepare()` copies a
  checkout's committed files only (an untracked file stays out) with its commit, keeps the copy when a workspace is
  recovered, mounts nothing without references, and copies a package-folder reference as it is; an environment reference
  falls back to its default and is absent without either; malformed defaults are refused.
- `tests/test_pi_development_workspaces.py`, `tests/test_problem_packs.py`, `tests/balsamic/test_layering.py` and the full
  suite (counts in the PR).

## Not done

- N1's allowlist does not shrink. Both files lose every FLRL name, but `agents/development_runtime.py` still names
  "grating" in the project's old identifiers (the `grating-implementation-workspace` image, `grating-<id>` container names,
  the `grating.development` label), which renaming would orphan running workspaces, and `agents/development.py` still
  points the coding brief at `libraries/grating-mask-search`, which F4 replaces. The roadmap's "Done when" expected a
  shrink; it comes when those names are renamed (a deployment change) and with F4.
- References are copied once, when a workspace is first prepared. A workspace opened before this change keeps the
  `/references/flrl` copy it already has, whatever its problem; a recovered workspace keeps its first brief.

## Acceptance test

On a lab where the FLRL checkout is beside the Balsamic repository (or `GRATING_FLRL_REFERENCE` is set in the launcher's
environment) and coding workspaces are enabled:

1. Open a MEENT grating campaign, approve a proposal for coding, and open its coding workspace. In the workspace's
   terminal or file view, `/references/flrl` holds the FLRL code, and the assignment (`.campaign/assignment.md`) ends with
   a "References" section that names `/references/flrl` as the FLRL authors' reference code.
2. Open a campaign on a non-MEENT problem (for example the bounded quadratic example) and open a coding workspace there.
   `/references` holds no `flrl` folder, and its assignment has no "References" section and no mention of FLRL (unless a
   paper is configured in the launcher, in which case the section lists only the paper).
3. With a paper set as `paper_reference` in the launcher, both workspaces list the paper under "References".
