# R3 — The bus refuses work outside the active mandate

State: implemented and tested (2026-10-27); the refusals are checked live by the acceptance test below.

## What was wrong

Layer: mandate. Staying within a request rested on the prompt: the compute guard checked only compute, and nothing checked
that a command was the kind of work its request allowed, that it was for a proposal the request named, or that the
request's deadline had not passed. R1 recorded mandates and R2 proposed them, but an expired or spent mandate, and a class
its template does not allow, refused nothing.
Invariant: INV-06 (prompt to code), INV-R1-3 (updated), INV-R3-1 to INV-R3-4 (new, next to INV-R2-3).

## Not done

- Autopilot's commands (actor `autopilot`) are still checked by its own cap guard, not by a mandate (R4).
- The chat has no dial and no Close button: `close()` exists, the researcher cannot press it yet (R7). Until then a mandate ends by its
  deadline, its envelope or its stop condition.
- The lead's instructions still say in prose that stages start only when a request covers them (R6 removes what the guard now enforces).
- A request that has had a Screen mandate cannot fall back to Explore once the Screen ends: new work waits for a new mandate. An Explore
  the request already used is not renewed.
- An agent creating a proposal with status `finalist` (`hypothesis.create`, class propose) is held by the fidelity gate (V3), not by the
  mandate.
- The lead is not woken when a mandate's deadline passes unless approved runs were still to start; it learns it from the state block
  and the refusal. The researcher is told only for mandates they granted whose end stopped something, not for an automatic Explore that
  is spent.
- The experiment operator's instructions still mention keeping the experiment rules; under a mandate other than Run the campaign it is
  refused and has to ask. R6 or a later prompt change may say so.

## Acceptance test

Start Balsamic with a campaign that has a problem and two proposals, and the lead agent switched on.

1. Ask the lead to stop one of the proposals ("Stop H02, it is too slow"). With no go-ahead it does not stop it: it asks you with one
   Inbox card for a Screen mandate (or says it needs one). Approve it; the proposal is stopped.
2. In a new message, ask for a screen of H01 only and approve the card with a deadline (for example 30 minutes). The runs start. Then ask,
   in the same message's conversation, for a run of H02. The lead says the approved screen covers H01 only and asks again; nothing starts
   for H02.
3. After the deadline, runs that were going keep going; the lead starts nothing new for that request, and says so if asked, but it can
   still report what the runs found. If it tried to start more, or approved runs had not started yet, the Inbox shows one notice that the
   screen has ended (and how many approved runs did not start).
4. Ask for several short probes in one message. The first ones start without a card; once they add up to your go-ahead threshold
   (Monitor, Resources), the next one is not started and the lead asks for a Screen mandate instead.
5. Your own actions (starting a run on Experiments, stopping a proposal on Hypotheses) work as before, whatever the mandates.
