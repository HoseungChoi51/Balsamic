# N1 — The domain-names ratchet

State: implemented and tested (2026-10-27); no live check needed, the part changes tests and docs only.

## What was wrong

The core (`src/optimization_framework`) is meant to name no domain, but nothing stopped a new file from naming one. 27 of
its files name MEENT, RCWA, gratings, FLRL or the deflector today, and any change could add a 28th without a test noticing.
The invariant register had the guarantee "the core names no domain" as `none` (INV-27).

## What changed

| Change | Where |
|---|---|
| A ratchet test: the files of the core whose text names a domain (`meent`, `rcwa`, `grating`, `flrl`, `deflector`, case-insensitive, as a word or the start of a camel-case part, so `integrating` does not count; `GRATING_*` environment variable names do not count) are listed in `NAMES_A_DOMAIN`. The test fails when a file off the list names one, and when a listed file no longer does, so the list only shrinks. The failure says which files and what to do | `tests/balsamic/test_layering.py` `test_no_new_file_of_the_core_names_a_domain` |
| The allowlist, generated from the code at the commit (every file under the core, `.py`, `.md`, `.json` and the rest, `__pycache__` aside): 27 files | `tests/balsamic/test_layering.py` `NAMES_A_DOMAIN` |
| A test of the ratchet on a fixture tree: a clean tree passes, a new domain name (in code, in Markdown, in a camel-case name) is caught, and a cleaned file left on the list is caught | `tests/balsamic/test_layering.py` `test_the_ratchet_catches_a_new_domain_name_and_a_cleaned_file` |
| INV-27 moves from `none` to `code`, with the allowlist as its known gap | `docs/invariants.md` |
| The register's seeded-rows test anchored INV-27 on "Closed by N1"; it now anchors it on `NAMES_A_DOMAIN` | `tests/test_invariants.py` |

## Checked

- `tests/balsamic/test_layering.py` and `tests/test_invariants.py`: 22 passed.
- Adding `# meent` to `campaigns/commands.py` (a file off the list) makes the ratchet fail and name that file.
- The full suite: see the PR for the counts on its head.

## Not done

- The 27 files still name a domain. Phase 6's N2 to N8 move the domain out and shrink the list in the same PRs. Some
  entries name only the project's old name in paths and service titles (`grating-lab`, `grating-implementations` in
  `implementations/api.py`, `implementations/client.py`), not domain logic; they count because the roadmap exempts only
  `GRATING_*` environment variables, and they leave the list when those names are renamed.
- `src/dqn_meent` and `src/balsamic` are not scanned: the first is the MEENT problem's own package, and the service layer
  is outside the core.

## Acceptance test

None: the part adds a test and changes no behaviour of the app. It shows as the test
`tests/balsamic/test_layering.py::test_no_new_file_of_the_core_names_a_domain`, which fails when a change makes a new file
of the core name a domain, and INV-27 reading `code` in `docs/invariants.md`.
