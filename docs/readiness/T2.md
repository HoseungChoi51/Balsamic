# T2 — The moderator's synthesis is checked

State: implemented and tested (PR #44, 2026-10-27; brought up to `main` after Phase 4 on the same day); the live S12 check is Hoseung's.

## What was wrong

Layer: evidence. The moderator's synthesis is a claim about the reviewers' verdicts, and nothing compared it with those records.
Invariant: INV-13 (updated), INV-T2-1.

- **The synthesis was prose.** The discussion moderator delegated reviewers, set statuses with `hypothesis.status` and
  ended a round with a reply in prose. The verdicts were records, but nothing compared the reply with them: the moderator
  could say a proposal stands while a reviewer rejected it, and nobody would see the disagreement unless they read both.
- **Statuses were not checked either.** The moderator could set a proposal it had reviewed to `investigating` over an
  objection, or archive one every reviewer said to test, and nothing noted it. (The concept-review gate on runs still kept
  an agent's proposal with an objection from running.)
- Part R's last "Not done" item: "the moderator's synthesis of the results rests on its instructions and the notice;
  nothing checks it".

## Not done

- **Live S12.** The "Done when" item "live S12 records a synthesis with no standing against the tally" needs a model run;
  it is Hoseung's (below).
- No refusal: a standing or a status against the tally is recorded and shown, never refused (item 6).
- The rule for `rejected` counts any archived proposal as a stop. V1 has landed since; the rule does not yet read the stop's typed outcome (for example, to treat `implementation_invalid` differently from `adequately_assessed_deprioritized`).
- A round is the moderator's current request: the reviewers it asked since that request opened. A synthesis is needed
  only when it asked a `proposal_reviewer`; a round of specialists alone (no verdicts) needs none.
- Statuses are compared with the tally of any proposal that has verdicts on its current revision, not only the
  proposals of this round.
- The moderator's closing reply is told to link the synthesis; nothing checks that it does.

## Acceptance test

Use a campaign with the lead agent switched on, autopilot off, and at least one proposal on the Hypotheses page that has
an obvious flaw (for example, a method that is not installed).

1. In the chat, write: "Have the discussion moderator review proposal H01 with a skeptical domain analyst and a proposal
   reviewer, and tell me the verdict. Nothing else." Wait for the lead's reply.
2. Open Hypotheses, then the Review rounds tab. The newest round, run by the discussion moderator, shows a "synthesis"
   box under its request: the moderator's summary, and a line for H01 with its standing (for example "rejected"), the
   reviewers' tally ("reviewers: test 0 · revise 0 · reject 1") and the moderator's reason.
3. If the standing agrees with the verdicts (a rejected proposal the reviewer rejected), there is no "against the
   verdicts" badge. If you see one, hover it: it names the review the standing goes against. That is the case this part
   makes visible; note it in the release check.
4. The moderator's reply (on the Hypotheses page, and in what the lead tells you) links Review rounds, and the lead's
   reply agrees with the synthesis.
5. Optional: on the Hypotheses page, ask the moderator directly to set a proposal every reviewer said to test to
   archived. The round shows a "status against the verdicts" badge on that proposal, and the status still changes.

Live eval, at this PR's merge commit or the Phase 7 tag: `uv run python scripts/run_lead_evals.py --scenarios S12
--repeats 3`. Compare with the baseline: S12 passes as before, and its new check `synthesis_matches_tally` passes (a
synthesis recorded, no standing against the tally).
