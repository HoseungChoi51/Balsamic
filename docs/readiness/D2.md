# D2 — `FunctionPlugin`, function conformance, seeded workers

State: implemented and tested (PR #35, 2026-10-27); not live: no library offers function methods until F3 generates
one from the charter, and the live check is Hoseung's after F4.

## What was wrong

Layer: none. The part fixes no failure; it lets a library offer D1's plain functions as methods.
Invariant: INV-D2-1, INV-D2-2 (added).

D1 made a function a method, but only a test could hand one to the worker. A library of functions needed three things
before it could reach the lab: listing its methods without running its code in the server, a contract check that runs
the problem's own evaluator, and hashing that is the same in every worker, so a method that iterates a set of strings
replays.

## What changed

| Change | Where |
|---|---|
| `FunctionPlugin`: a library subclasses it with `MODULE = "<pkg>.methods"` and `REPRESENTATIONS`. `methods()` reads the `METHODS = {id: {name, description, hypothesis_id?, parameters?, parameter_properties?, …}}` literal from the module's source (`find_spec`, then `ast.literal_eval`) and never imports it; a non-literal, missing or malformed `METHODS` is refused with what to fix. `create()` imports the module, in the worker only, and wraps the function in a `FunctionMethod` with the method's default parameters; a listed id with no function is refused. `problem(instance)` is the seam F3 fills with the library's own problem object | `optimizers/functions.py` |
| `conformance.check_function(plugin, method_id, instance, *, seeds=(0, 7), max_evaluations=50)`: every candidate valid, the same candidates and the same end for the same seed, a checkpoint at half the run continuing to the same run, and a clean end (returned, or stopped at the cap with its thread ended). It evaluates on the problem the instance resolves to, so a library's own evaluator is what runs, each distinct candidate once | `optimizers/conformance.py` |
| Workers start with `PYTHONHASHSEED=0` in both launch paths. The isolated worker started Python with `-I`, which ignores every `PYTHON*` variable, so it now starts with `-s -P -S` and no `PYTHONPATH`; the launcher sets `PYTHONPATH` for child processes once it runs. The environment is still only Balsamic's (`--clearenv`), and at startup only the standard library is importable, as under `-I` | `execution/service.py` `_start_trial()`, `execution/isolation.py` `command()`, `execution/attempt_bootstrap.py` (comment) |
| A frozen capture pins the methods module's source: no static import reaches it, so without this a changed method would keep the run's scientific digest | `optimizers/plugins.py` `OptimizerPlugins.worker_modules()`, `execution/provenance.py` `capture()` |
| "Plain-function methods" | `docs/optimizer-plugins.md` |
| Rows `INV-D2-1` (listing runs none of the library's code) and `INV-D2-2` (the digest covers the methods module), next to the other library rows | `docs/invariants.md` |
| `tests/test_readiness.py` accepts the keyed ids (`INV-D2-1`) in an `Invariant:` line, as `tests/test_invariants.py` already does | `tests/test_readiness.py` |

## Checked

- `tests/test_function_plugins.py` (14 tests): listing does not import the methods module (`sys.modules`), and gives
  complete descriptors with the library's representations, the hypothesis id, defaults and parameter schema; a module
  that imports a package only the worker has is still listed; a non-literal, missing or malformed `METHODS` fails loudly
  without importing; `create()` imports the module and the worker runs the function to `method_finished`; a listed id
  without its function is refused; `check_function` passes a seeded one-shot method (returned) and a seeded endless one
  (cap), uses the problem's own evaluator once per distinct candidate, and fails a method that reads the clock (the same
  seed proposed another candidate) and one that proposes a candidate outside the bounds; a worker the service starts has
  `PYTHONHASHSEED=0`; a frozen capture lists the methods module in its scientific files and its digest changes when a
  method changes.
- `tests/test_framework_isolated_host.py::test_an_isolated_worker_hashes_with_a_fixed_seed_and_starts_with_only_the_standard_library`:
  two isolated workers print the same `hash('balsamic')` with hash randomization off, and a `resource.py` in the captured
  code does not shadow the launcher's import. Checked to fail with the old `-I` launch (different hashes) and with
  `PYTHONPATH` left in the startup environment (the capture shadows `resource`).
- `tests/test_function_methods.py` (D1), `tests/test_optimizer_plugins.py`, `tests/test_readiness.py` and
  `tests/test_invariants.py` pass. The full suite in parallel: see the PR.

## Not done

- Nothing runs `check_function` on a library before it enters the lab: INV-23 stays `none` until H6.
- No library uses `FunctionPlugin` yet; F3 generates one (with `problem(instance)` returning the library's problem
  object) and F4 starts coding workspaces from it.
- `check_function` assumes a deterministic evaluator only in that it scores each distinct candidate once; it does not
  test a method against an evaluator's noise.
- Listing imports the library's parent package (`find_spec` of a submodule does), as loading its plug-in module already
  did; the generated library's `__init__.py` is generated code (F3).
