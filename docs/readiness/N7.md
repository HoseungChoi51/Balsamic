# N7 — No MEENT paths in execution

State: implemented and tested (PR pending, 2026-10-27); the migration of a copy of the live store is Hoseung's.

## What was wrong

Layer: none: the part removes domain defaults from the generic path; it fixes no agent failure.
Invariant: INV-N7-1, INV-N7-2 (added); INV-27 (its known gap shrinks from 28 files to 25).

A task or trial stored without a `problem` was silently treated as a 1D MEENT grating (`problems.resolve("meent_grating",
…)` in `create_trial()`, `validate_trial()`, `run_recipe()` and the runtime profile's subject), and an implementation spec
without a problem id was for `meent_grating`. Trials of the old execution contract would start
`dqn_meent.workspace.worker`, a module that no longer exists, so resuming one failed in the worker instead of being
refused. MEENT's version was written into the core's runtime identity, and the confirmation source snapshot was hashed
under a MEENT folder name.

## What changed

| Change | Where |
|---|---|
| A migration gives every stored task and trial without a problem the one its problem pack's `legacy.problem` hook resolves (a trial with no recognisable settings takes its task's). Records no pack recognises keep none, are listed in a `problem.migration_unresolved` event, and are refused by id where a problem is needed. It changes nothing when run again, and the workspace runs it at every start. `python -m optimization_framework.execution.problem_migration <workspace directory>` runs it on a copy and prints the counts and the unresolved ids | `execution/problem_migration.py` `migrate()`, `required()`, `main()`; `execution/service.py` `Workspace.__init__` |
| The four `meent_grating` fallbacks are gone: a record without a problem is refused naming it | `execution/service.py` `create_trial()`, `validate_trial()`, `run_recipe()`; `execution/runtime_profile.py` `subject()` |
| MEENT's pack declares two legacy hooks: `problem` (an old record's physics as `meent_grating`) and `runtime` (MEENT's version and the lab fork's commit) | `src/dqn_meent/pack/legacy.py`, `src/dqn_meent/pack/__init__.py` |
| `ProblemRegistry.legacy(name)` returns the installed packs' legacy hooks of that name, each pack once | `evaluation/registry.py` |
| The runtime identity takes Python and the core's numerical libraries, then what each pack's `legacy.runtime` adds. For MEENT the result is the same dictionary as before, so recorded identities still match | `execution/source.py` `runtime_identity()` |
| Trials of the old execution contract are read-only history: starting, resuming, extending or continuing one is refused with "Experiment … ran under the old execution contract … kept as read-only history"; the scheduler always starts `optimization_framework.execution.worker` | `execution/service.py` `read_only_history()`, `_start_trial()`, `control()`, `continue_trial()` |
| The confirmation source hash is taken over the snapshot's `code` folder, which is what it hashed already (the MEENT folder name was dropped by `scientific_hash()`) | `execution/service.py` `_start_trial()`, `evaluation/legacy_confirmation.py` `snapshot_confirmation_code()` |
| `ImplementationSpec.problem_id` is required. Stored specs keep the id they were saved with; a cached version without one is refused by `compatible()`. A coding workspace's spec that names none takes its hypothesis's problem, or the problem all the campaign's current tasks are on, and is refused when that is not one problem | `implementations/models.py`, `implementations/bridge.py`, `agents/development.py` `_with_problem()`, `implementations/legacy.py` |
| N1's allowlist loses `execution/service.py`, `execution/runtime_profile.py` and `execution/source.py` | `tests/balsamic/test_layering.py` `NAMES_A_DOMAIN` |

## Checked

- `tests/test_problem_migration.py` (7 tests): fixture records of both kinds (a grating task and trial storing only their
  physics, a trial storing only its task, and a task and trial no problem recognises) migrate to the problem
  `meent_grating` resolves, the unknown ones are reported, and a second run changes nothing; a reopened workspace has
  migrated them and the command reports on the copy (exit 1 with the unresolved ids); validating, running a recipe on and
  profiling a record left without a problem are refused naming it; resuming, extending, continuing and starting an
  old-contract trial are refused with the message, and reading it works; the runtime identity has the MEENT key from the
  pack, once for both MEENT problems; a pack without the hook adds nothing; a spec without `problem_id` is refused.
- The ratchet and the register: `tests/balsamic/test_layering.py`, `tests/test_invariants.py`.
- The full suite (counts in the PR).

## Not done

- `evaluation/legacy_confirmation.py` still keys confirmation conditions on `problems.resolve("meent_grating", physics)`
  (`physical_condition_key()`), and `implementations/models.py` refuses MEENT as a candidate dependency: both stay on
  N1's allowlist. `implementations/bridge.py` keeps an RCWA sentence about the relaxed-gradient method (N8's).
- The migration has not run on the live store; Hoseung runs it on a copy (below).

## Acceptance test

1. Make a copy of the lab's data folder and start the app on the copy. It should start as usual, and the old campaigns
   should open with their tasks and experiments as before.
2. Open an old campaign that has experiments from before the current execution contract (the oldest grating runs). Each
   experiment's page and results should show. Choose Resume or Continue on one of them: the app should refuse with
   "ran under the old execution contract … kept as read-only history", and nothing should start.
3. On a current campaign, start, pause and resume an experiment: it should behave as before.
4. If any old record could not be given a problem, running `python -m optimization_framework.execution.problem_migration
   <copy of the data folder>` lists it by id; expect an empty `unresolved` list.
