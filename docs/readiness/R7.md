# R7 — The mandate dial in the chat

State: implemented and tested (2026-10-27); the dial, the bar and Close are checked live by the acceptance test below.

## What was wrong

Layer: mandate. What a request allowed was set only by the agents: the lead proposed a mandate (R2) and the researcher could
answer its card, but could not say with their own message how much the request allowed, see the mandate it worked under, or
close it. Graded delegation was autopilot on or off plus two thresholds, and the original plan's three modes survived only as
the `autonomy` field, read by the confirmation scheduler.
Invariant: INV-R7-1 to INV-R7-3 (new, next to INV-R3-4).

## Checked

- `tests/test_mandate_dial.py` (12 tests): a message sent with Screen grants its request a Screen mandate with the researcher's resolved
  decision and a consent for that request, its envelope and deadline; the lead proposed nothing, its state block names the mandate, and
  a 20-minute run (past the go-ahead threshold) starts under it and is charged to the consent; the bar's read shows the mandate, what is
  left and its deadline; after `mandate.close` the next agent command in that request is refused ("has ended: it was closed") and the
  agent cannot grant itself Explore again. That consent is request-only: another request's 20-minute run is refused and not charged to
  it (and the refusal offers no go-ahead), the same request's run is covered and charged, and an agent's approved card naming no
  proposals still pays for a third request's run (decision 4). Answer and Explore sent with a message are granted at once with no decision; under the
  researcher's Answer a run is refused and the agent's Explore proposal is refused, while a Screen card is still filed; envelopes on
  Answer or Explore, a Screen without worker time, an unknown proposal and a mandate with no thread are refused. An agent can neither
  send a message with a mandate nor close one. With autopilot on, `mandate.close` of its standing mandate is refused with the pointer to
  the switch, the mandate stays active, and the bar's read shows it granted by autopilot with no Close; switching autopilot off closes
  it, and a mandate granted with a message still closes from the chat. `autonomy` maps onto the default template, the researcher's setting wins and changes
  only it, and an agent cannot set it. The confirmation scheduler's two checks give, for manual, guided and delegated, what they gave
  before, and follow the researcher's template when one is set.
- `tests/balsamic/test_panels.py`: a panel button whose `agent.message` carries a mandate is refused.
- Playwright `mandate-dial.spec.ts` (4 tests): with Screen as the campaign's default, Send opens the envelope form and sends nothing; "Grant
  and send" sends `agent.message` with the envelope; the bar shows the Screen mandate, what is left and its deadline; Close sends
  `mandate.close` and the bar says it is closed. Answer sends at once with its template; a slash command carries no mandate; Cancel keeps
  the text. Autopilot's mandate shows with no Close and "switch autopilot off to end it". The default mandate is set on the Resources
  page with `campaign.update`.
- `tests/test_mandates.py::test_every_operation_the_bus_lists_has_a_mandate_class` passes with `mandate.close`; the R1–R5 mandate
  tests, `tests/test_invariants.py` and the full suite pass.

## Not done

- **The dial follows `autonomy` until the researcher chooses a default, and starting the agent team sets `autonomy` to delegated**
  (as before R7), so on most campaigns the dial starts at Screen and every message first asks for an envelope. Hoseung kept this
  (27 October 2026); the researcher sets Explore (or another) as the default on Monitor › Resources. Setting the default does not
  change `autonomy`, and changing `autonomy` does not clear a default the researcher set.
- The envelope form does not offer the proposals a Screen is for (the API takes `hypothesis_ids`): a Screen granted from the chat covers
  any proposal's work, within its own request only.
- The form starts at fixed values (Screen: 30 min, no coding workspace, no model envelope, 2 h deadline; Run the campaign: 120 min, 1
  coding workspace, no model envelope, 24 h), not values read from the campaign or from the last mandate.
- Closing a mandate does not wake the agent working for its request: it learns from its state block or from the refusal of its next
  command.
- The dial is in the chat's composer only: a page agent's desk and the Inbox's answer box send no mandate (their requests have Explore,
  or the agent's own proposal).
- A Screen or Run the campaign granted with a message leaves its resolved decision in the Inbox's "Recently resolved" list.
- `campaigns/drafts.py` still reads `autonomy` for an agent's draft launch; R7 moved only the two confirmation readers.

## Acceptance test

Start Balsamic with a campaign that has a problem and a proposal, and the lead agent switched on.

1. Beside Send in the chat there is a small dial. Open Monitor › Resources: under the compute thresholds, "Default mandate" shows which of
   the four is the default (Screen for a campaign whose delegation is "delegated", until you choose). Choose Explore, go back to the
   chat: the dial now shows Explore.
2. Turn the dial to Answer and write "Run two one-minute probes of coordinate search". The lead does not start them: it says this request
   allows answering only (it may offer a card for more). Above the chat a line reads "Answer · This request · …, granted with your
   message". The dial is back at Explore.
3. Turn the dial to Screen and write "Screen coordinate search with two seeds, ten minutes each". Press Send: a small form opens with worker
   time, coding workspaces, model spend and deadline, and nothing is sent yet. Set the worker time to 40 minutes and press "Grant and
   send". No card appears in the Inbox; the lead starts the runs. Above the chat: "Screen · This request · left: 40.0 min of worker time ·
   deadline …", and what is left goes down as runs start. While they run, send another message with Explore asking for a 20-minute
   run of something else: the lead does not start it on that go-ahead (it asks you with a card instead), and the Screen line's worker
   time does not go down for it.
4. Press Close on that line while the lead is still starting the runs. The line now reads "closed by you: new work is refused". Runs
   already going keep going; the ones not yet started are not started, and the lead says the mandate was closed when it reports. Your
   next message is a new request, with the mandate you send it with.
5. Type `/probe` with the dial at Screen: the probe starts with no form. Press Send with Run the campaign and then Cancel: the form
   closes and your text stays.
6. Switch autopilot on (the Autopilot switch in the top bar) and open the Autopilot thread from the thread menu. Above its chat, a line
   reads "Run the campaign · Autopilot · left: … · granted by your autopilot switch", with "switch autopilot off to end it" where Close
   would be. Switch autopilot off: the line goes away, since the mandate is closed.
