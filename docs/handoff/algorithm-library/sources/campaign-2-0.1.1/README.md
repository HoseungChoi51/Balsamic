# 단일 오븐 주문 순서의 총 고객 대기 시간 최소화

오전 6 h시 0 min분부터 단일 오븐에서 주문 8개를 연속으로 굽는 순서를 선택한다. 주문별 양의 지연시간을 동일 가중치로 합산한 총 고객 대기 시간을 최소화한다.

결정변수는 주문 8개를 누락·중복 없이 포함하는 굽기 순열이다. 각 주문의 굽는 시간과 픽업 시각은 고정되어 있으며, 첫 주문은 같은 날 오전 6 h시 0 min분에 시작한다. 한 주문의 굽기를 중단하거나 나누지 않고, 완료 즉시 다음 주문을 시작한다.

계산에는 시작 시각으로부터 경과한 분을 사용한다. 각 주문의 완료 시각은 순열에서 그 주문까지의 굽는 시간을 누적한 값이다. 고객 대기 시간은 완료 시각에서 픽업 시각을 뺀 값의 양의 부분이며, 일찍 완료된 주문으로 늦은 주문의 지연을 상쇄하지 않는다. 총 고객 대기 시간을 최소화하며 동점인 순서는 모두 허용한다.

픽업 시각은 강제 마감이 아니다. 예열·교체·냉각·포장 시간과 추가 작업자 제약은 모델에 포함하지 않으며, 굽기 완료를 픽업 준비 완료로 취급한다. 입력은 결정론적이다. 결과에는 주문별 시작·완료·픽업 시각과 대기 시간, 지연 주문 수와 최대 대기 시간을 기록한다. 기준 순서와의 비교도 같은 계산식으로 수행하되, 이 문제 정식화 단계에서는 기준값이나 최적값을 계산하지 않는다.

## Implementation (0.1.1)

- `oven_subset_dp` implements H01 (`hypothesis_pi_command_0b42ea54006b2c2a5b485550fad5b0f2`): last-job subset DP, choosing the smallest last job on ties, not the lexicographically smallest schedule. Inspection records `states` (empty included), `transitions`, and construction `elapsed_seconds`.
- `oven_mdd` implements H02 (`hypothesis_pi_command_e8ed11294c079e0ad59272cdc7964f46`): repeatedly minimizes `(max(d[j], t+p[j]), p[j], j)`. Inspection records `priority_calculations` and construction `elapsed_seconds`.
- H03 uses the host's existing `swap_search`; it is not implemented or registered here.

Both methods deterministically propose exactly one schedule and finish after its observation. The adapter uses a custom ask/tell wrapper behind the FunctionPlugin listing, retaining diagnostics in final inspection. Charging, caching, and deadlines remain with the host. JSON checkpoints preserve initial, pending, and finished states and validate method/evaluation identity. DP bounds are published only after independent prefix re-evaluation and an agreeing successful observation with the actual evaluator identity; synthetic conformance observations do not certify proofs.

Pure helpers `core.subset_dp(durations, due)` and `core.modified_due_date(durations, due)` return dictionaries with `order`, `objective`, `elapsed_seconds`, and the counters above. Helpers support variable job counts (including empty), finite nonnegative fractional durations and finite negative or large due dates. **DP supports at most 20 jobs**, rejected before allocating exponential tables; time is O(n 2^n), space O(2^n). MDD takes O(n^2) time and O(n) space. Arithmetic uses supplied numeric values without integer truncation; ordinary floating-point rounding applies.

The charter-bound evaluator requires all eight configured orders. It returns raw nonnegative minute values for the primary objective and every declared metric, with ordered `metadata['schedule']` rows (`order_index`, `order_name`, zero-based `position`, `start_min`, `completion_min`, `pickup_min`, `wait_min`). Times are relative to start; already-relative dues are never shifted. `metadata['start_clock_min']` is display-only. Metadata retains the charter-derived metric directions with a caveat: per-order waits are descriptive, not maximization utilities. The immutable charter is unchanged. Invalid permutations are rejected before the evaluator count increments; evaluator restore validates evaluation identity.

The tests include independent permutation oracles and last-job tie checks, dynamic MDD/ties, fractional/zero/negative-due inputs, schedules and all metrics, invalid candidates, seeded replay, checkpoint boundaries, termination and generated conformance tests. They are software validation only, not campaign experiments. No scientific runs, optimum/baseline/comparative report, or second workspace were launched.
